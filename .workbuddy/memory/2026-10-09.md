### 关键决策

1. **顶栏徽章是个按钮** —— 未授权时它是"唯一能解决问题的地方"的入口。现场看到
   "点了没反应"的第一反应就是点那个红徽章。
2. **跨层传"停摆"用 `provide`/`inject`，不逐层传 prop**。执行入口分散在控制台（App 自己）
   与编辑页「试运行」（第 4~5 层）。为一个只读布尔量穿过四个与授权无关的组件是 prop 钻孔。
3. **集合瓦片不置灰**：它点开的是只读导航弹层，执行发生在里面的子按钮上。
   禁掉集合等于"没授权连看都看不了"，而看板本来就是特意放行给现场看"为什么不能用"的。
4. **置灰与"发送中"用不同手法**（`opacity+grayscale+not-allowed` vs `saturate+progress`）：
   共用滤镜会让用户把"没授权"误读成"正在发送"。
5. **`Warn` 档也出横幅（黄），`Off` 档不出横幅**：前者是"拦不住但要让你知道"，
   后者天天空挂一条只会训练用户忽略横幅。
6. **生效档位与配置档位不一致时必须解释**（配置 `Warn` + 有试用记录 ⇒ 生效 `Enforce`），
   否则现场会以为配置没生效。

### ⚠️ 过程中揪出并修掉一个真 Bug —— 试用天数多送一天

徽章显示「**试用 31 天**」。根因：`GenerateTrialAsync` 按 `起算日 + TrialDays` 算到期日，
而 `ed` 的语义是**当日末刻**才到期 ⇒ 10-09 起算的 30 天试用落到 11-08，
含首含尾 **31 个自然日**；更明显的后果是 **1 天试用会跨到第二天**。
改为 `+ (TrialDays - 1)`（"N 天试用 = 含起算日在内的 N 个自然日"），
守门用例只拿记录里两个日期做差、不掺"现在是几点"，因此在 23:59 与 00:01 跑结论一致。

### 几个不显然的决策

1. **实例必须显式抬档 + 关试用**（`Enforcement=Enforce` + `AutoTrial=false`）。
   默认是 **`Warn` + 首启自动 30 天试用** —— 不抬不关的话"全新实例一上来就是可用的"，
   **闸门根本没有机会被观察到**。为此给 `run_scenario` 加了 `extra_args`，而不是为授权场景
   单写一套起停逻辑。`Warn` 档交给集成测试的三态矩阵，冒烟不重复。
2. **必须真发 UDP，不能只看 `/readyz` 的 `listener` 字段**。`listener=false` 只是
   "监听服务自称没跑"；真正要证明的是**绕开 Web 界面直接往对接码端口发码也触发不了动作**
   —— 这正是当初坚持要在监听层再设一道闸门、而不是只靠 HTTP 中间件的理由（中间件管不着 UDP）。
3. **为免"真 UDP"沦为伪证，先 PUT 一份配置**：如果配置里本来就没有对接码，
   "发码没反应"是必然的、证明不了任何事。脚本先写一个带对接码的按钮（动作指向 sink），
   "收到 / 没收到"才有区分力；顺带把"未授权时配置写入放行"也断言了。
4. **B 段是分水岭**：只有"用另一把私钥签的、格式完全正确的文件被拒"，
   才能把**真的在验签**与"能解码就算过"区分开。改一个字符那种篡改会同时破坏 JSON，
   服务端可能以 `Malformed` 拒绝 —— 那样测的就不是验签了。
5. **签发工具自动探测 + `to_native_path`**：Git Bash 里 `DOTNET_ROOT=/c/Users/...`，
   Windows 上的 Python 用 `os.path.isfile` 判定必然为假 ⇒ 表现为"dotnet 明明装了却探测不到"。
   加一层 `/c/x/...` → `C:/x/...` 转换。探测顺序：`--tool` → 环境变量 → `dist/*.exe` → `tools/**/*.dll`。

### ⚠️ 顺手揪出并修掉一个潜伏真 Bug —— 数组 splat 是"按位置"传参

```powershell
# ❌ build-installer.ps1 原来：数组 splat 按**位置**填充位置参数，元素不会被当成参数名
$portableArgs = @('-DotNetRoot', $DotNetRoot, '-NodeRoot', $NodeRoot, ...)
```
