### 1.1 需求⑤ 的两条关键结论

1. **配置态 ≠ 实时态**。`udp.enabled/port` 是"**我要它**怎样"，`host.udpChannel` 是"**它现在**怎样"
   （由客户机上报）。"指令不生效"多源于把前者当后者。`null` ＝ **还没上报**，与"明确说没在听"是两件事。
2. **SignalR 的实参个数必须与签名严格一致**（C# 默认参数**完全不生效**）
   ⇒ 给 `Heartbeat` 加可选参数会让**老客户端直接调用失败**，所以状态上报走**独立方法**
   `ReportUdpChannel`（与心跳同一个上报周期）。

### 1.2 需求⑥ 的三件事

`AgentPathPicker`：① 缓存（`CACHE_TTL_MS = 20s`，**键带 `targetId`**，失败的也缓存）；
② **看得见的加载态**（旧列表变灰 `.entries.stale` ＋ 顶部 `.status-line.busy`，
且加载中**不清空**旧列表、`pick()` 里挡住误点）；
③ 显式「记为此机默认目录」（`PUT /api/agents/{id}/path-memory`，两个字段都可选＝不传就不动那一项）。
`DistributionPanel`：**乐观覆盖层**（`remembered`），因为 `agents` 是父级只读 computed。

### 1.3 🔥 本轮查出的**真缺陷**：「点了浏览没反应」

在一台**从没记过目录**的机器上点「浏览…」→ 面板打开、然后**什么都不发生**。

根因（四步）：`targetDirs` 的键"只在有记忆值时才补" ⇒ `v-model="targetDirs[id]"` 传 `undefined`
⇒ 子组件 `props.modelValue.trim()` 抛 TypeError ⇒ 调用点 `void openAt()` **把异常一起吞掉**。

修法：组件给 `modelValue` 补默认值 `''`（并在 `startPath`/`adopted` 里 `?? ''` 兜底）；
父级**无条件**写入 `targetDirs[id]`（哪怕空串，键也必须在）；
UI 探针新增 **Q 段**监听 `Runtime.exceptionThrown` / `console.error`。

**教训**：`void asyncFn()` 是故意丢结果，但它连**异常**一起丢了。
"点了没反应"的现场，第一件事是**看控制台**。本轮原有的 40 条断言，**没有一条**能发现它。

### 2.1 🔥 真缺陷：「装完就能用」此前是**断的**

`AgentRuntime.RunAsync` 只在 `RestoreFromStore()` 成功（本机有配置 ⇒ 触发 `Applied` ⇒ `OnConfigApplied`）
**或**连上中心之后才调 `Apply` ⇒ 一台**从没连过中心、也没有本机配置**的新机器，
`Apply` **一次都没被调用** ⇒ `netstat` 里 **8090 压根不存在**。
需求① 表面上是"加个策略"，实际上补的是这个**从未跑通的口子**。

### 2.2 新的判定规则（**两个决定者**，优先级从高到低）

1. `Agent:Tasks:Enabled=false` ⇒ **永不听**（压过一切）；
2. **是否连着中心**：
   - **未连接 ⇒ 一律监听** —— **忽略** `udp.enabled=false`；端口**沿用配置**，
     越界**回落 8090（而非 Stop）**；
   - **已连接 ⇒ 配置说了算**（老规矩：`enabled=false` ⇒ Stop）。

**吊销也被算作"未连接"** ⇒ 吊销后照听（＝接受"被吊销 ≠ 失去 UDP 控制"）。
连接状态变了**只翻 `standalone` 标志 + 刷文案，不重绑端口** —— 重绑会留一个**收包空窗**，
网络抖动时可能正好丢掉一条 DOWN。`standalone` **刻意不参与** `Matches` 比较（否则会走进重绑分支）。

### 2.3 `_lastUdpConfig`：吊销后端口不能被悄悄改回 8090

`OnRevoked` 里 `_configs.Clear()` 会把 `_configs.Current` 清成 **null**；
而吊销后**仍要继续听** ⇒ 端口必须沿用**吊销前那一份**。没有这个字段，
端口会静默回到默认值，且**没有任何日志**。

### 2.4 顺带修掉的两个隐患（自查发现，非报错）

| 隐患 | 症状 | 修法 |
|---|---|---|
| 状态文件**非原子写** | `File.WriteAllText` 覆盖写 + 托盘/页面**并发读** ⇒ 读到半截 JSON ⇒ `Read` 返回 null ⇒ 托盘**闪一下"未连接"** | 写 `.tmp` 再 `File.Move(overwrite:true)`；另加进程内 **`WriteGate` 锁**（写它的线程不止一个） |
| `Connected` 的**状态机空洞** | 原本只在 `RunConnectedAsync` **两端**赋值 ⇒ 异常从中间跑出去时字段**停在 true** | 主循环 `catch` 里补 `Connected = false` + **重新决策通道** |

另：心跳每 10 秒刷"最后通信时间"**刻意不经过** `UpdateStatus`（后者的契约是"状态变了才通知"，
而 `Status` 一个字都没变）；两者共用抽出的 `WriteStatus()`。

### 2.12 🔥 本轮踩到的坑：删除拦截"先删掉、再报失败"

打交付产物时四个脚本**全部非零退出**，报的是：

但它**不是**仓库里的代码 —— 是本机对 `Remove-Item -Recurse -Force` 的**外部拦截**（走 genie-trash）。
最坏的地方在于：**目录真的被删掉了，脚本却收到失败** ⇒ 中止在"准备输出目录"那一步，
结果是 `dist/win-x64`、`dist/agent-setup`、`dist/installer` **凭空消失**（本轮第一跑就是这么丢了三个目录）。

**绕法（已验证）**：**先让目标目录不存在**，脚本内部 `if (Test-Path) { Remove-Item }` 就整段跳过 ⇒ 走"缺什么补什么"：

1. `dist/win-x64` / `dist/win-x64-service` 都缺失 ⇒ 单独跑 `build-portable-exe.ps1`（`PORTABLE=0`）；
2. `dist/win-x64-service` 已存在 ⇒ `build-installer.ps1` 走"payload 已存在"分支，不再删它（`INSTALLER=0`）；
3. `dist/agent` 与 `dist/agent-setup` 本轮已由**嵌套调用**重建成功（21:39/21:41），**就不再重跑** `build-agent.ps1`
   —— 在它已存在时重跑＝先删掉再中止，产物会直接消失。

## 三、M4.11：移除客户机之后**加不回来**（修复，#255–#261）

> 根因、改法、变异测试与坑位见 **`REF-M4-Agent.md` §29**；方案侧见 `docs/M4-…方案.md` §31。

### 3.0 症状（用户原话）

> "在服务端的客户端列表中移除某个客户机之后，无法再次连接添加该客户机。"

补一句现场才知道的事：**重启客户机上的 Agent 也没用**，唯一绕法是去那台机器上删掉本地状态目录。

### 3.1 根因：**两个洞，缺一不可**（同一个形状："查不到"被当成"一切正常"）

| # | 位置 | 旧行为 | 后果 |
|---|---|---|---|
| ① | `AgentHub.Heartbeat` | `…FirstOrDefault(h => h.Id == id)?.IsRevoked == true` ⇒ 查不到时 `?.` 短路成 `false` ⇒ 走 `else` 照常 `MarkSeen` + 回 ack | 服务端早把它忘了，客户端还以为在线；**长连接变僵尸**，永不再注册 |
| ② | `AgentRuntime.EnsureRegisteredAsync` | 只要"本地凭据的 serverUrl + machineKey 与当前一致"就 `return cached` | 记录被删后这把 `agentKey` 必然 401，而客户端把 401 当普通连接失败 ⇒ **拿废钥匙无限重试**（退避到 60 秒封顶） |

洞①的副作用：`MarkSeen` 内部是 `GetOrAdd(id)` —— 服务端会替**一台已经被删掉的机器**记心跳。

### 3.2 修法

- **服务端**：`Heartbeat` + `RequireAgent` 在"快照里没有这台机器"时 **`Context.Abort()`**
  （`RequireAgent` 另回一个 `unregistered` 应答）。依据是快照的装载规律：
  启动一次 + 每 60 秒刷新 + **刷新失败沿用旧快照** + 注册成功立刻 `ApplyChange` ——
  ⇒ **"库里有的机器不在快照里"只可能是刚被删掉的那台**。
- **客户端**：新增 `AgentRegistrar.IsCredentialRejectedAsync` —— 连接失败后**拿一次普通 HTTP 请求去问**
  （`GET /api/agents/{id}/config` + `X-Agent-Key`），**只有 401/403 才算被拒**；
  命中则 `_identity.Clear()` + 清 `_cachedCredentials` + `_transfers?.ClearSession()`，下一轮重新注册。

**为什么不去猜 SignalR 异常里的状态码**：那依赖"401 一定被塞进 `HttpRequestException.StatusCode`"，
不同版本 / 不同传输的包装方式并不一致 —— 一旦不成立，修复就**静默失效**。
"问一句"把判定和 SignalR 内部实现彻底解耦，代价只是连接失败后多一个请求。

### 3.3 一个必须知道的语义取舍（用户决策）

`AskUserQuestion`：**被吊销的客户机也一样自动回来**（不与"移除"做区分）。于是：

| 场景 | 现在 |
|---|---|
| 被**移除** | 立刻以**新 Id** 回来 |
| 被**吊销**（离线） | 也立刻回来（没有 5 分钟退避） |
| 被**吊销**（在线） | 走既有 `Revoked` 消息 + 5 分钟退避后回来 |

⇒ **"吊销"更弱了**，但这是**本来就存在**的性质（免凭据准入下重新注册必定复活，
`AgentEnrollmentService` 早已写明"要真正下线一台机器，去那台机器上卸载，而不是靠吊销"）。
另外：被移除的机器重新注册后，**本机那份配置会随双向同步推回中心** —— "移除"不清配置。

### 3.4 验证（最终态）

| 项 | 结果 |
|---|---|
| `dotnet build` | **0 警告 0 错误** |
| `dotnet test`（三条命令分别跑） | Core **796** / Agent **104** / 集成 **385** = **1285，失败 0** |
| 冒烟新增 **H 段「移除之后加得回来」**（8 条） | `--only agent` **167 PASS / 0 FAIL**（上轮 159） |
| **变异 A**：关掉服务端两处 `Abort`（客户端修复保留） | **H 段 FAIL** —— 机器没回来（客户端根本不知道） |
| **变异 B**：关掉客户端清身份（服务端 Abort 保留） | **H 段 FAIL** —— 机器没回来（拿着废钥匙一直重试） |
| 全量冒烟 `run-all.py` | **9/9 场景通过** |
| 前端真重嵌 | `verify-dist.sh` ⇒ `index-BZ4Ty4Ew.css` / `index-D5HYp8R1.js` 与磁盘 wwwroot **一致** |

H 段的关键实证（不是"跑了"，是"看到了"）：

```
[PASS] 移除后客户机自动重新注册回来（≤150s）
[PASS]   是**新记录**而不是旧记录被复活（Id 变了） —— Id 2 → 3
[PASS]   客户机日志里出现了第二次「注册成功」 —— ['注册成功：Id=2…', '注册成功：Id=3…']
[PASS]   日志里说明了原因是「凭据被中心作废」
```

**H 段的四条设计纪律**（防"假绿"）：判据用列表的 `state`（不是详情的 `connected`）；
**Id 必须变**（硬删后重新注册必然新插一行）；日志里必须出现**第二次「注册成功」**
（否则"列表里又有了"可能是别的机器补上来的）；**必须说出原因**。

### 3.6 🔥 本轮踩到的坑

1. **复现时"证据被测试自己的清理删掉了"**：H 段第一版照抄 D 段的 `finally`，
   `shutil.rmtree(state_dir)` 把客户机的 NDJSON 日志一并删掉 ⇒ 脚本只说"没回来"，
   而"为什么没回来"的那几行**已经不存在了**。改成**失败时保留状态目录**并打印日志路径。
2. **`HttpRequestHeaders` 的索引器只有 getter**：`request.Headers[name] = value` **编译不过**（CS0021），
   必须用 `TryAddWithoutValidation`。
3. **`run-all.py` 默认打 `dist/` 产物**：改完代码后 `dist/` 还是旧的 ⇒ 会拿上次打包的客户端
   验这次的代码。开发期把被测服务端指到 `.artifacts-check/bin/ControlServer.Server/debug/`，
   同源解析会自动挑同一批构建的客户机（debug 路径一次 1.5 分钟，比 dist 快 3 倍）。
4. 变异测试的 `false && …` 会带出 CS0162（不可达代码）——**预期**，不是修复引入的。
