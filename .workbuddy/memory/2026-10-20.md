## M7.14 顶栏「挂起」＋ 列表「结束会话」✅

用户要求：把远控窗口悬浮面板右上角的关窗按钮挪到**全屏左侧**并改名「挂起」；
在机器列表里新增「结束会话」，用于在**挂起状态**下结束会话。

### 改动

- 顶栏顺序：`[挂起] [全屏] [收起参数] [重连] [断开]`（原来 `✕` 在最右）。
  `closeWindow()` → `suspendWindow()`（名字不改，半年后没人记得它和「断开」的区别）。
- 列表行：`v-if="sessionToResume(a.id)"` 才有「结束会话」，复用 `endSession()`。
  新增 `endSessionOf(agent)`：`stoppingIntentionally` **只在这一路正是本窗口在看时才置**
  （无脑置上会掐掉**别的机器**正在跑的重连）；`wasWatching` 时补 `teardownViewer()` + 清 `windowAgentId`，
  否则窗口标题还挂着"推流中 · 12 fps"，而那一路上一个字都不会再来。
- `.rd-machine-actions` 加 `display:flex; gap:8px`（两个按钮不挤）。

### 为什么改成「挂起」不只是改名

`✕` 的通用语义是"关掉/销毁"，而它其实是这几个按钮里**最安全**的一个（什么都不销毁）。
现场点了以为会话被结束，于是**不敢点**，最后改用「断开」来收窗口 —— 而「断开」会掐掉所有观众。
且最右端本来就是危险动作（`断开`）的位置语义。

**「结束会话」补的是「挂起」带出来的缺口**：挂起后窗口没了、画面上一个按钮都没有，而这一路还在推流。
原来要收掉只能"再点进去 → 点断开"（先建一次 4K 解码再拆它）⇒ 有这条缺口，「挂起」就是半残功能。

## 远控悬浮面板「文件传输」可行性（方案，未改代码）

产出 `docs/M8.1-远控悬浮面板文件传输方案.md`。结论与事实（后续实施可直接引用）：

- **场景答案**：裸机（无 Server 无 Agent）用**浏览器**即可与 Agent 机双向传，链路
  `浏览器 ─HTTP─> 中心 ─SignalR信令+HTTP(Range/分块)─> Agent`，**不需要新协议**。
  前置：能访问中心 8899 ＋ 管理员（远控页本身 AdminOnly）＋ 授权（建单归 Gated）。
- **反例**：现场只有两台、没有中心 ⇒ 不可行；两台都装 Agent 也不行（Agent 无横向通道）。
  唯一入站口 UDP 8090 是明文、只认 DOWN/RESTART/音量，**不得扩成文件通道**。
- **双向已有**：`push`（`POST api/distributions`）／`collect`（`POST .../collect`，`SourcePath` 任意绝对路径）；
  字节走 `api/files/uploads` 分块 + `GET api/files/{id}/download`（Range）。
  裸机侧只用 4 个端点、今天就在用 ⇒ 缺的只是"面板里的两步编排"。
- 🔴 **授权分类易错**：`LicenseGate` 只把**建单**归 Gated；上传/下载/浏览归 Allowed ⇒
  授权过期时"传得上去、看得见、发不出去"，面板必须说清是哪一步被拒。
- **七条限制**：浏览器只能手动下载到下载目录／自动接收必须装 Agent／下发同名**直接覆盖**
  （`File.Move(overwrite:true)`）／写有白名单（默认 `inbox`）读无白名单／单文件模型（无目录无多选）／
  4GB 上限·8MB 块·会话 24h／两跳中转（磁盘 ×1、带宽 ×2、串行）。
- **缺口**：任务列表无 `?agentId=` 过滤（面板会漏老任务）／「上传成功但建单失败」须是独立状态
  （不能并入"传输失败"，重试应从建单开始）／上传会话只活内存／同名覆盖无提示／临时副本无回收概念。
- **两条好性质**：离线可建单（上线补领）；远控断线不影响传输（字节走 HTTP）。
- 不做：流式直通（失去补领/续传）、WebRTC P2P（STUN/TURN、破坏无入站、新信任模型）、扩 UDP 8090；
  **长期收发最便宜的替代 = 给那台机器装 Agent**。
- 工作量约 5–6 人日。待拍板：仓库副本保留策略（是否新增 `kind=transient`）、同名覆盖确认、HTTPS 另存为。

# M7.16 帧率旋钮 ＋ 播放延迟按帧率算（第一阶段 1080p/60）

## 三个"旋钮转了但没效果"的静默失效

1. 🔴 **帧率被档位折平**：`targetFps = Min(maxFps ?? profileFps, profileFps)`，
   默认档 `auto` 解析为 12 ⇒ 页面选 20/30/60 **全变 12**，无任何一层报错。
   ⇒ 改 `RemoteQualityProfiles.FoldTargetFps` = `Clamp(requested ?? profileFps, 1, 60)`
   （**请求值优先，档位只提供默认值**），两个调用点（`Open` / `SetQualityAsync`）同改。
   ⚠️ **帧率与档位是两个旋钮**，别再乘/取小；60 fps +「低」档是合法组合（糊但不许自动降回 12）。
2. 🔴 **建会话不带档位**：`POST /api/remote/sessions` 从不上报 `quality` ⇒ 每路新会话从 `auto` 起步。
3. 🔴 **重建/重连丢档位**：`lastConnectParams` 三条写入路径只有两条补了 `quality`，漏 `startSession`。

## 延迟：60 ms 固定缓冲改成按帧率买两帧

`web/src/playbackLatency.ts`：`clamp(2 × 1000/fps, 20, 60)` ⇒ 60 fps 时 33 ms（省 27 ms），
≤30 fps 时仍是 60。**进程级单值 + 每帧现读**（音画必须按同一延迟排期）。
抽成纯模块的理由：**退避/延迟这类规则没有任何界面证据**，写在组件里只能靠人读代码。前端 **226**（+7）。

## 🔴 顺带挖出的真 BUG：ROI 从来没接过线（M5.5 整块死码）

`WindowsGpuFrameEncoder` 三个成员（`Regions` / `SetViewport` / `TryEncodeSurfaceRegions`）**全实现了**，
但类声明只写 `: ISurfaceFrameEncoder` ⇒ 宿主判据 `encoder is not IRegionSurfaceEncoder` **恒为真**：

- M5.5 的**视口 ROI 一次都没生效过**（`SetViewport` 永远返回"不支持只编视口"）；
- M5.5 的**分块编码是死码** ⇒ 三屏拼接永远落到 MJPEG 缩略图（M7.10 那句"只能是缩略图"其实是被这个 bug 逼出来的）；
- 帧头坐标系 `keepsNativeSize` 恒 false，与接口契约（1:1 不缩放）不符。

修：声明加 `, IRegionSurfaceEncoder` ＋ **编译期钉子**（`private static IRegionSurfaceEncoder ContractPin(...) => encoder;`
删接口即 CS0029，已实测会咬人）。⚠️ 这类"实现写好了但没接线"没有日志没有告警，
**判据只能是类型层面**（`is` / 编译期转换），不能靠"用一下看看"。

## 服务端晚于客户端启动 ⇒「永远连不上」（已修）

**现场证据**（`C:\ProgramData\ControlServer.Agent\logs\log-2026-10-20.ndjson`）：
09:15:21 启动时"服务端地址：未指定（将用 UDP 广播自动发现）"，随后 09:16–09:20 每 42–48 秒一轮
`连接中心服务端失败 (192.168.3.33:8899)`，**一次广播都没发过**；09:20:09 人工把地址改成
`192.168.101.57:8899` → 09:20:57 注册成功（改完还等了 48 秒）。⇒ 不是网络，是**缓存地址被当成了终结答案**。

**四条根因**（都不报错）：
1. `ResolveServerUrlAsync` 里 `credentials.dat` 的 ServerUrl 有值就 `return`，`DiscoveryClient` 永不调用；
2. 退避是裸 `Task.Delay` ⇒ 改地址要等睡满（实测 48 秒）；
3. 每轮连接失败都做一次 20 秒凭据探测（中心不可达时一轮 40 多秒）；
4. `AgentRegistrar.RegisterAsync` 把 HttpClient 超时也 `throw` ⇒ 普通"不可达"变成 Error「客户端主循环出错」。

**改动**：
- 新增 `agents/ControlServer.Agent/Transport/ServerAddressResolver.cs`（纯判定）：人指定的地址永不替换；
  缓存地址连续失败 **2 轮**才广播；发现不同就换址（凭据属旧中心→重注册）；`SameAddress` 比 authority。
- 新增 `Transport/ServerConnectFailure.cs`：拒绝/不可达/超时⇒跳过凭据探测；401/403⇒直接重注册；
  `ConnectionReset` 仍要探测（可能是认证层在拒）。探测预算 20s→**5s**。
- `AgentRuntime`：`_addressFailures`／`_adoptedUrl`／`_lastResolveNote`（按**不含数字**的文案去重）；
  `IterationOutcome.ResetBackoff`（换址立刻重试）；固定地址连不上时广播一次只**记线索**。
- `AgentServerOverride`：`SemaphoreSlim(0,1)` 唤醒信号＋`WaitForChangeAsync` ⇒ 改地址当场重连；
  `ConsumeChangePending` 顺手把信号排空。
- `RegisterAsync` 超时改成 `status=network` 的正常失败（只有调用方取消才抛）。

**实证**：`.build/repro-late-server.py`（假凭据指 `10.255.255.1` ＋假中心 UDP 19998，不碰真中心）**6/6**；
首次失败→采用发现地址 **21 秒**（旧代码永不）。脚本本身踩过一个坑：Windows UDP 的 ICMP 10054 会让
`recvfrom` 抛 `ConnectionResetError`，假中心必须 `continue`，否则静默退出被误读成"广播没找到"。

## 10:30–10:45 「https://0.0.0.0:8443 报不安全」定位与处置（M5.3 运维口径）

### 结论：两个**互相独立**的原因，装证书只能解决第二个

1. **0.0.0.0 不是访问地址**（装任何证书都救不了）。它是「监听所有网卡」的占位符，
   浏览器/DNS/证书校验都不接受它作目标：`SslStream.AuthenticateAsClient("0.0.0.0")`
   直接抛「IPv4 地址 0.0.0.0 和 IPv6 地址 ::0 未指定，不能作为目标地址使用」。
   而且 `LocalCertificateAuthority` 的 SAN 里**永远不可能**有 0.0.0.0 ⇒ 即便能连也是名称不匹配。
2. **根 CA 没装进信任存储**。浏览器只认公共 CA，私有 CA 签的证书必然是「不安全」。

### 实证（同一台中心，装根证书前后）
| 地址 | 结果 |
|---|---|
| `https://localhost:8443` | 通过 |
| `https://127.0.0.1:8443` | 通过 |
| `https://DESKTOP-9VFHRMA:8443` | 通过 |
| `https://192.168.101.57:8443` | 通过 |
| `https://0.0.0.0:8443` | **失败**（未指定目标地址） |

证书本身没问题：`certutil -verify` 确认签发者匹配；SAN 覆盖
`DESKTOP-9VFHRMA / localhost / 127.0.0.1 / ::1 / 192.168.101.57`；有效期到 2029-10-20。

### 已做
- 根证书已装入 `LocalMachine\Root` + `CurrentUser\Root`（指纹 `ED8B31C0…CAFB06`）。
- 新增 `deploy/windows/trust-ca.ps1`（UTF-8 BOM、语法过）：自提权装 LM\Root、
  按指纹去重、`-Uninstall` 可撤、**装完做真实 TLS 握手验证**而不是只看存储里有没有。

### 🔥 新铁律（并入 MEMORY.md #48）
- **Windows 不允许静默写根证书存储**：`Import-Certificate` 在非交互会话直接报
  「此操作中不允许使用 UI」；`X509Store.Add` 到 CurrentUser\Root 也会弹安全警告。
  唯一顺的路径＝自提权到管理员 → 写 `LocalMachine\Root`（只需点一次 UAC）。
- **验证信任必须看真实握手**。「存储里有这张证书」是假验证：装错 store（进了"个人"）、
  指纹对不上、Firefox 用自己的存储（不吃 Windows 存储）—— 三种都会显示"已安装"但仍报红。

### 待办（代码层面根因，未改）
- `ServerAddressRegistry.DescribeHost()` 把 `IPAddress.Any` 渲染成 `https://0.0.0.0:8443`
  写进启动日志；`ServerAddressService.CurrentUrls` 回落 `http://0.0.0.0:8899`；
  `TrustEndpoints.HttpsUrlsOf` 回落 `https://0.0.0.0:8443`。
  三处都把**监听地址**当**访问地址**给运维 ⇒ 照着敲必失败。
