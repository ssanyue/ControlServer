> 表里的"已修 **7** 行"对应 **4 个必修项** —— 同一处修复的不同侧面各自记账
> （例如"算法换了""旧值还能验""超长口令不再喂哈希"是三行、一处改动）。

**必修 4 项**（全部已修、全部有回归用例）：

1. **口令用单轮 SHA-256 存储** → PBKDF2-HMAC-SHA256 210k 迭代，旧值登录时**就地升级**；
2. **登录端点没有任何限速** → 按来源 IP 的固定窗口（默认 5 分钟 20 次）；
3. **`Server:Security:AllowedCidrs` 是个死配置**（写了却全仓 0 处消费）→ 真正接线，且解析失败拒绝启动；
4. **基线安全响应头缺失** → `nosniff` / `X-Frame-Options: DENY` / `Referrer-Policy: no-referrer`。

外加一处**顺带修掉的**：口令哈希换算法后，"账号不存在"与"账号存在"的响应时间差从微秒级放大到几十毫秒，
会在局域网里被稳定测出**用户名枚举** —— 已在同一处补上时序对齐（见 §2 第 6 行）。

## 5. 真机验证（**不是** TestServer）

改了四处管线中间件，只靠集成测试不够：TestServer 与真 Kestrel 在 `RemoteIpAddress`、限速中间件的执行时机、
响应头落地这几件事上行为不同。所以另外起**真进程**在回环上跑了一遍（临时数据目录、临时端口，不碰现场库）。

| # | 验证 | 方法 | 结果 |
|---|---|---|---|
| 1 | 三条安全头真的在响应里 | `GET /trust/info` 看响应头 | ✅ 三条都在（见下方实测输出） |
| 2 | 限速在真 Kestrel 上生效 | `PermitLimit=3`，连打 5 次错口令 | ✅ 前 3 次 `401`，第 4/5 次 `429` + `Retry-After: 300` + `{"message":"登录尝试过于频繁，请稍后再试。"}` |
| 3 | 配了白名单后**本机仍然能访问** | `AllowedCidrs=10.0.0.0/8`，从 `127.0.0.1` 访问 | ✅ `200 OK`（回环无条件放行 —— 否则现场就是"服务起来了但本机打不开"） |
| 4 | 白名单写错**拒绝启动** | `AllowedCidrs=oops/99` | ✅ 进程退出码 **1**，日志 `[FTL] 来源网段白名单…拒绝启动：「oops/99」的地址部分无法解析…` |

第 1 条的实测输出：

```
HTTP/1.1 200 OK
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer
```

复现方式（`<PORT>` 换成一个当时空闲的端口，铁律 12）：

```powershell
$env:Server__Storage__DataDir          = "$env:TEMP\m62-smoke"
$env:Server__Http__Urls                = "http://127.0.0.1:<PORT>"
$env:Server__Https__Enabled            = "false"
$env:Server__Startup__AutoOpenBrowser  = "false"
$env:Server__Tray__Enabled             = "false"
$env:Server__Startup__SingleInstance   = "false"

```

⚠️ 两点坑（都踩了）：
- **`curl` 可能被系统代理接管**，回的是 `502 upstream connect failed` —— 真正的信号是"连不上"，而不是"服务坏了"。用 `--noproxy '*'` 或直接开 socket 发请求。
- **构建时 `exe` 还在跑** ⇒ `MSB3026` 文件被锁。先停进程再编译（本条已在 MEMORY 铁律里）。

### ⚠️ 这一条会改变现场行为（升级前必看）

`AllowedCidrs` **从来没有生效过** —— 所以历史配置里可能躺着一个"当年随手填的、从未被验证过"的值
（例如从别处抄来的 `192.168.1.0/24`，而现场其实是 `10.x`）。升级之后它**会真的生效**，
于是那台机器上**除回环以外的所有访问都会被 403**。

处置（三件事，都在升级窗口内做）：

1. **升级前先看一眼** `appsettings.json` 里的 `Server:Security:AllowedCidrs`；不确定就把这一项**清空**（空＝不限制，保持旧行为）；
2. 升级后看启动日志：出现「来源网段白名单已启用：N 条」就说明它在拦人；
3. 万一被挡在门外：本机 `https://127.0.0.1:8443` **仍可访问**（回环无条件放行）—— 它至少能证明"服务是活的、只是白名单在拦"，而不是"服务挂了"。要改回来只能改 `appsettings.json` 里那一项并**重启服务**（白名单在启动时读取，界面上改不到它）。

> 这条正是 M6.2 的价值所在 —— 不是"加了个功能"，而是**把一个假的开关变成真的，并且它的第一次生效必须有人知道**。
