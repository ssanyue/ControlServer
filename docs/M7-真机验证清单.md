## 2. 多屏拼接：「全部显示器」能用，但只能走 MJPEG

**先把上一版这里写错的话纠正掉**：之前写的是「功能还没做完、当前行为是明确拒绝」。
**在管线层面这不准确** —— 真实行为是分层的：

| 层 | 请求「全部显示器」时发生什么 |
|----|------------------------------|
| 中心 / 页面 | 正常下发，屏列表里本来就有 `全部显示器（N 块拼成 W×H）` |
| GPU 硬编 | 在建管线**之前**以 `GpuPipelineStage.Screen`（环境问题级）拒绝，理由正确 |
| 托盘 | 按回退链**回落到 MJPEG**，并把「停在哪一级」写进日志 |
| MJPEG | 走 GDI 抓屏器，**一次 `BitBlt` 抓整块虚拟桌面** ⇒ 画面是**全的** |
| 页面 | 会话信息显示实际编码 **MJPEG**，并附一句「拼接只能走 MJPEG」 |

⇒ 所以这一项**不是「功能没做」**，是「**拼接没有硬编**」。功能是通的，代价是编码从硬编变软编。

**缺的那一半是什么**

拼接走硬编。一句话原因：`IDXGIOutputDuplication` 一个设备只能对一个 output 建 duplication，
拼接要「多 output 抓 → GPU 合成到一张画布 → 再进编码器」，并且指针合成、脏区、
`ACCESS_LOST` 恢复全要改成多路。

**为什么值得做**：MJPEG 在 1440p 只有 12–25 fps 软编（契约注释里写着的），两块 4K 拼起来
（7680×2160）会更慢 —— 大屏场景下 MJPEG 那条路会明显不够用。

**为什么没直接写**：本机只有一块屏，多 output 那条路**一次都跑不起来**。
本仓反复踩过「代码写了、真机从没跑过」（§10 第 1 条那个假 FAIL 就是同一类）。
另有一个结构性前提没解决：多路 duplication 必须**共用一个 D3D11 设备**，
而现在 `D3D11GpuContext.TryCreate` 是「按屏建一次设备」——
先要把设备的所有权改成「一个适配器一个设备、多个 output」，这属于会动到已验热路径的改动。

**要验 / 要继续做，需要**：一台**两屏以上**的被控机（最好一横一竖、分辨率不同，
能一次暴露偏移与尺寸算错）。

**判据（就在这样一台机器上，验今天的行为）**
- 下拉框能选到「全部显示器（N 块拼成 W×H）」，且 W×H 等于各屏并集
  （副屏摆在主屏左边时，并集原点在**负坐标**上）。
- 选它之后画面是**整块桌面**：左边/上面副屏的内容也要看得到，比例不变形。
- **鼠标点到副屏上，事件落在副屏**。这一条验的是 `ScreenDescriptor.Left/Top` 那对偏移
  —— 单屏机上它恒为 0，这类错在开发机上**永远看不出来**。
- 会话信息里的编码是 **MJPEG**，说明里写着「拼接只能走 MJPEG」（这是本轮的改动：
  以前这句话只落在被控端日志里，中心页面上看不到）。

## 3. 8K 全链路

**前置**：被控机能输出 7680×4320（或视频墙 2×2 拼 4K），编码器支持该分辨率（HEVC 更现实）。

**步骤**：`POST /api/remote/sessions` 带上 8K 那块屏的 `screenId`，看中心侧读数。

**判据**
- 中心 `stats.framesReceived` 持续增长（不是 0，也不是 1 帧后卡住）。
- 帧头里 `frameWidth/frameHeight` 是 **7680×4320**；分块时 `tileCount > 1` 且每块
  `regionX/regionY` 拼起来正好覆盖整幅（页面上的「拼不起来」计数保持 0）。
- 页面「画面分辨率」显示 7680×4320（不是某一块的宽度）。
- 内存/显存不持续上涨（8K BGRA 一帧 132 MB，漏一帧就是肉眼可见的涨）。

**已知风险**：编码器尺寸上限、分块阈值、显存不够时的表现。**挂账**里一直记着"8K 未验"。

## 4. 4K60 ≤ 100 ms

**前置**：4K60 被控机 + 千兆内网 + 观看端硬件解码（Edge/Chrome 有 WebCodecs）。

**判据**
- 页面「帧时延」稳定 **< 100 ms**（p95，不是平均值）。
- 中心/被控端两路 fps 都接近 60。
- 丢帧不再增长。

**注意**：**单机自环（同一台机器既当被控端又当观看端）证明不了跨机时钟同步** ——
冒烟里那段帧时延只能说明"链路在动"。真正的端到端时延必须两台机器。

## 5. Linux 客户端能力（本轮新接的）

刚接上的三条（`src/ControlServer.Platform.Linux/`），**代码有单测、真机没跑过**：

| 能力 | 实现 | 真机上要确认什么 |
|------|------|------------------|
| 温度 | `/sys/class/thermal` + `/sys/class/hwmon` | 数值**对得上** `sensors` 命令；虚拟机大概率没有传感器（那时应显示「—」而不是 0） |
| 开关机记录 | `last -x`（读 `/var/log/wtmp`） | 能读出 boot/shutdown；**断电**那次要显示成"异常"而不是"正常关机" |
| 整机电源 | `systemctl poweroff/reboot --no-block` | 非 root 时**失败原因**要能看到 polkit 那句原文 |
| 音量 | `wpctl` / `pactl` / `amixer`（按序探测，降权到登录用户执行） | ⚠️ **已接线，待真机**：见 §5.1 末尾那四条判据 |

### 5.1 音量为什么还没通（2026-10-18 核查，纠正上一版说法）

上一版这里写的是「Linux 侧没有托盘宿主（`NoopTrayIconHost`），这个端口没人消费」。两处都不准确：

1. **`NoopTrayIconHost` 不是 Agent 的**。它是**中心 Server** 在非 Windows 上用的托盘占位
   （`src/ControlServer.Server/Program.cs:731`），跟被控端的会话侧执行者没有关系。
2. **「没人消费」只是表象，真正卡住的是三件事**（任何一件都会让"接上线"变成"接了个假的"）：

| # | 卡点 | 证据 |
|---|------|------|
| ① | 服务进程里**根本没有注册** `IAudioController` | `grep IAudioController agents/ControlServer.Agent.Service/` = **0 处**；只有 `Agent.Tray/Program.cs:118` 自己 `new` 一个 |
| ② | 实现**在构造函数里就探测**，用的是服务进程的环境 | `LinuxAudioController` 构造函数调 `Detect()`；服务是 root/systemd，`XDG_RUNTIME_DIR` 不是用户的 ⇒ `wpctl` 连的是 root 的 PipeWire 上下文，三个后端一个都探不到 |
| ③ | 就算探测过了，**执行身份也不对** | `wpctl`/`pactl` 走的是 `$XDG_RUNTIME_DIR` 下的 socket。root 在系统会话里改音量 ⇒ 命令返回 0，**用户桌面上的音量一格都不动**（`HostAudio.cs` 的接口注释写的就是这条） |

⇒ 所以 Linux 音量缺的不是一行注册，而是「**目标会话解析 ＋ 降权执行 ＋ 延迟探测**」这三件配套。
**2026-10-18 已补齐**（方案与实测见 `docs/M7.3-Linux音量与会话侧执行.md`）：
`LinuxSessionLocator` 找最近登录的图形会话 → `runuser -u <user> -- env XDG_RUNTIME_DIR=…`
（无 runuser 时 `sudo -n`）→ 探测延迟到首次使用、失败 5 秒短缓存。
`AgentCommandExecutor` 在会话通道 `IsSupported=false` 时回落到本机实现，
因此**中心的音量按钮在 Linux 上会真的生效**（Windows 上该分支永不进入）。

**真机上要看的四件事**：①日志出现「音量后端：PipeWire（wpctl），会话用户 alice（wayland，会话 2）」
②alice 登录桌面时，中心点「提高音量」→ **桌面音量条真的动**
③注销到无图形会话再点 → 回"没有图形会话登录"，不是超时
④同时登录两个用户 → 调到的是**最近登录**那个（不是列表第一个）。

⚠️ **同一个缺口还会影响以后要加的能力**：Linux 侧仍然**没有**会话侧执行者
（`Agent.Service/Program.cs:233` 非 Windows 直接注册 `UnavailableSessionCommandChannel`），
所以「延时启动程序」在 Linux 上仍不可用；`remote-stream` / 剪贴板同理
（Linux 平台层本来也没有抓屏与输入注入实现）。**那不是漏了一项，是这一层整体没建。**

**命令**
```bash
# 温度：和我们的读数比
cat /sys/class/thermal/thermal_zone*/type; cat /sys/class/thermal/thermal_zone*/temp
# 开关机：看它到底写了什么
last -x -F --time-format=iso -n 10
# 音量后端到底是哪个
wpctl get-volume @DEFAULT_AUDIO_SINK@ || pactl get-sink-volume @DEFAULT_SINK@ || amixer get Master
```

**判据**：页面上温度不是 `0`；`wtmp` 里那条 `crash`/`shutdown` 在我们这边对应成了
「异常」/「正常关机」；`last` 读不到（非 root、无 utmp 组）时页面说的是**权限原因**而不是空表。

## 8. 数据目录 ACL

**前置**：Windows 被控机，`%ProgramData%\ControlServer.Agent`。

**步骤**：把数据目录的 ACL 改成"普通用户不可读"，再用服务跑一次；然后把 ACL 恢复。

**判据**：目录不可读时，**启动失败要说清是权限**（而不是"配置为空"再自己重建一份空库，
那种表现是"重启后所有配置都没了"）。

## 9. 非安全上下文（局域网 http）

**为什么本机验不了**：冒烟的服务端只绑 `127.0.0.1`（`127.0.0.1` **是**安全上下文），
而换成局域网地址还要过 Windows 防火墙。

**步骤**：服务端 `Server:Http:Urls=http://0.0.0.0:8899`，放行防火墙，用**另一台机器**
打开 `http://<被控-IP>:8899`。

**判据**
- 顶部横幅说"不在安全上下文 ⇒ 没有声音"，并且**画面与键鼠照常可用**。
- 点「复制到本机」→ 提示"请在下面那段文字里手动选中复制"（`navigator.clipboard` 不存在）。

> 这两条的分支逻辑本机已用 init 脚本复现验证（浏览器实证里 C2 一节），
> 真机上要确认的是**"页面确实跑在 http 局域网地址上"**这个前提。

## 10. 顺带记一笔：本轮靠自动化抓到并修掉的三个真缺陷

不是"要你真机验"的，而是提醒**这套冒烟是干什么用的**：

1. **「点了没反应」的真因可以是产物旧**（这条经验来自已下线的隐私屏那一轮）：
   根因不是代码，是 `Agent.Service` 目录里的
   `ControlServer.Agent.dll` 还是 13:39 的旧产物（13:39 那版不认识 `privacy` 动作）。
   ⇒ 改了客户端**必须重发产物**；判新旧看启动自述，不要看源码。
2. **剪贴板"没有文本"被写成了"读取失败"**：被控端把解释塞进了 `note`，而页面按
   "有 note ⇒ 读失败"渲染 ⇒ 一句话自相矛盾，现场会去查一个没坏的东西。
3. **剪贴板读失败时页面完全收不到**：那条走的是 `Failure`，而中心到被控端是
   fire-and-forget ⇒ 用户点一下"读取"，页面还挂着上一次的内容。现已改成走 payload
   （`text=null, note=原因`），页面才真能显示「读取失败：原因」。
