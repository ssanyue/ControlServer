# M7.13 远程控制窗口 + 悬浮参数面板（含断线重连 / 热更改）

> 一句话：**远控页只剩"机器列表 + 一个连接按钮"，其余参数全部搬进远控窗口里的悬浮面板（连接/画面/控制/声音/诊断 五个分组），并补上"断线自动重连"与"连接中热更改"两条能力。**
> 实证过程中抓到两个真 bug（都是"看起来能用、实际是死路"的那种），已在同一轮修掉。

## 2. 断线重连

### 2.1 断线有两条完全不同的来路

| 来路 | 传输层 | 谁能救 |
| --- | --- | --- |
| 浏览器 ↔ 中心 WebSocket 断 | 断了 | SignalR `withAutomaticReconnect` + `rejoinActive()` 重新入组 |
| **被控端会话没了**（托盘重启 / 休眠 / 被中心清掉） | **好得很** | 只有页面能救 —— 必须**重新建一路会话** |

只做第一条，现场看到的是"画面黑着、实时通道显示已连接"。

### 2.2 状态条必须说三件事

> `1 秒后自动重连（第 1 / 5 次）—— 这一路结束了：管理员结束了这路会话`

只说"重连中"时，"它在努力"与"它卡住了"长得一样，而处置相反（等 vs 手动介入）。
所以：**为什么断 / 第几次 / 还有几秒**，三样都显示，并给「立即重连」「放弃并断开」。

### 2.3 退避规则抽成了纯函数

`web/src/reconnect.ts` + `reconnect.test.ts`（12 条用例）。原先是写在组件里的三段 `if`，
而它们**没有任何界面证据** —— 错了只是"重试得比该有的快/慢"，没人读就没人发现：

| 规则 | 不这么写会怎样 |
| --- | --- |
| `connecting` ⇒ 忽略 | 叠出两个建会话请求，第二个必然 409，且它的错误会盖掉真正的原因 |
| `waiting` ⇒ 只更新原因（合并） | 同一次断线被 `SessionChanged` 推送 + 5 秒轮询各报一次 ⇒ 一次断线烧掉两格次数，5 次只剩 2 次 |
| 次数用完 ⇒ `failed` | 被控端关机时无限重试 = 每 20 秒往中心打一次建会话请求，永远不会好 |
| `failed` ⇒ 忽略 | "放弃 → 又被拉回倒数"的循环，而用户什么都没点 |

退避表 `[1, 2, 4, 8, 16]` 秒（合计约 31 秒）。

## 3. 热更改 ≠ 重连（参数来源刻意相反）

| | 参数来源 | 语义 |
| --- | --- | --- |
| 「重连」/ 自动重连 | `lastConnectParams`（**刚才那一幕**） | 恢复断线前的画面 |
| 「按当前设置重建会话」 | **当前表单值** | 按我现在改成的样子重开一路 |

合成一个函数的话，用户改完下拉框点"重连"，会被悄悄恢复成旧参数 ——
而那看起来像"下拉框根本没生效"。

窗口**不关**：重建期间只是画面黑几秒，参数面板与悬浮位置都不动。
`抓哪块屏` / `帧率上限` 要重建才生效（它们是**建会话那一刻**下发给被控端的参数）；
`显示方式` 是纯本机缩放，即时生效，不需要按钮。

## 5. 实证抓到的两个 bug（本轮已修）

### 5.1 「接着看」这条路**从来不记连接参数** ⇒ 断线必然放弃

- **现象**：从列表点「接着看」进窗口，画面正常；一断线，状态条直接变
  `自动重连已放弃 —— 没有记住上一次的连接参数，请手动点「连接」。`
- **根因**：`lastConnectParams` 只在 `startSession`（页面自己**建**会话那条路）里写。
  而"别人开的那一路我点进去看"走的是 `openWindow(existing.sessionId)`，压根不经过那里。
- **为什么那条提示特别坏**：它让你"手动点『连接』"—— 可你刚点的就是连接。**死胡同**。
- **修法**：① 新增 `rememberParamsFromSession()`，从会话里反推参数（`targetFps` 当上限是安全的，
  只会不高于原来）；② `doReconnect` 在没有记录时用**当前表单**兜底，不再直接放弃。

### 5.2 断线那一刻窗口标题变成「机器 #0」

- **现象**：`<strong>{{ agentName(activeSession?.agentId ?? 0) }}</strong>`，
  会话一没 `?? 0` 就把标题写成「机器 #0」—— 看起来像"连到了另一台不存在的机器"。
- **修法**：新增 `windowAgentId`（**窗口归属**，只在打开窗口 / 换机器时写，不随会话状态变化），
  标题与「按当前设置重建会话」都用它。

### 5.3 顺带：窗口刚打开时「抓哪块屏」是空下拉框

那台机器正忙着推流时，问它要屏清单要等一轮，于是下拉框空着、下面还写着
「没有可抓的屏 —— 通常意味着那台机器没人登录」—— 而画面正以 2160×1440 在推。
修法：`openWindow` 里若 `screens` 为空就补读一次（`refreshScreens()`）。

## 6. 铁律沉淀（接 M7.11 编号）

36. 🔴 **凡是"重连/恢复"要用的记忆，必须在**每一条进入路径**都写。**
    "创建时记录"这个钩子只覆盖"自己创建"这一条；「接着看」/ 从列表点进去 / 分享链接打开，
    全都是**不经过创建**的入口。判据不是"点连接试试"，而是**从第二条路进去，再断一次**。
    写不全的表现是"自动重连已放弃"，而那条提示往往让你做一个你正在做的动作。

37. 🔴 **窗口/面板这类"当前实体"的展示不许 `?? 0` 兜底。**
    `agentName(activeSession?.agentId ?? 0)` 在会话消失时会画出「机器 #0」——
    一个不存在的实体，而它看起来像"连错了机器"。窗口要有**自己的归属字段**，
    生命周期比"会话"长（重连期间还得知道自己在修哪台机器）。

38. 🔥 **异步回报的能力（屏清单那类）要在"打开窗口"时补读一次。**
    判据是"窗口刚开时那个下拉框是空的"。这类能力的特点是：问下去要等被控端回一轮，
    而窗口打开的那一刻它往往还没回来 —— 于是面板里摆着一个空下拉框，
    外加一句与事实相反的"没有可抓的屏"。
