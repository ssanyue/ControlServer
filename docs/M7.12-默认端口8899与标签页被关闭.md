# M7.12 · 默认网页端口改 8899 ＋「标签页被 Edge 关掉」

> 两个需求，两条互不相干的根因。端口是配置改动，标签页是**浏览器保留键**的坑。

---

## 1. 默认网页访问端口：8080 → 8899

### 1.1 为什么要改

8080 是**代理软件与开发服务的默认落脚点**（Clash / v2ray / 各种脚手架），
本项目的 `install-service.ps1` 里早就写着这条经验：

> 目标机装了 Clash、v2ray、公司上网代理时，访问 `http://127.0.0.1:8080` 会被代理接管。

端口撞车时最难查的地方在于**它不报错**：服务可能起得来、也可能起不来（`端口被占用`），
而浏览器那一侧看到的是代理返回的东西，不像"本系统的页面"。

8899 不在常见代理/框架默认端口里，也不与项目其它三个号冲突（8090 Agent UDP、9998 发现、9999 对码）。

### 1.2 改了哪些地方（真源与派生）

| 位置 | 说明 |
|---|---|
| `src/ControlServer.Server/appsettings.json` | `Port` 与 `Urls` 两处（**当前真源**） |
| `src/ControlServer.Server/Options/ServerOptions.cs` | `HttpOptions.Port` 默认值 |
| `src/ControlServer.Server/Program.cs` | 两处 `GetValue("Server:Http:Port", …)` 兜底 |
| `src/ControlServer.Server/Services/ServerAddressService.cs` | 端口读取兜底 |
| `src/ControlServer.Server/Cli/HealthCheckCommand.cs` | `--health` 的探测端口 |
| `src/ControlServer.TrayAgent/Program.cs` | `DefaultPort`（托盘"打开管理界面"） |
| `src/ControlServer.Server/Properties/launchSettings.json` | 本机调试地址 |
| `web/vite.config.ts` | 开发期代理目标（`/api`、`/hubs`、`/healthz`、`/readyz`） |
| `run.cmd` | `PORT` 默认值（**GBK 编码，改动时别写成 UTF-8**） |
| `appsettings.sample.json`、`deploy/linux/*`、`deploy/windows/*.ps1`、`deploy/upgrade/*.ps1` | 部署物与脚本默认值、防火墙放行、提示文案 |
| `docs/*`（安装/运维/绿色版/Linux/授权/真机清单） | 面向现场的操作步骤 |

**刻意没动**：`ButtonAction.TargetPort` / `SubButton.TargetPort` / `ControlSettingsNormalizer.DefaultTargetPort`
（这是"按钮动作下发的目标端口"，是业务数据，与网页端口无关），以及
`AgentConfig.DefaultUdpPort = 8090`（客户机 UDP 指令通道）。

### 1.3 升级现场的四个注意

1. **已装过服务端**：防火墙入站规则还是 `TCP/8080`。要么重跑
   `install-service.ps1 -HttpPort 8899`，要么手工加一条 `TCP/8899` 放行，否则
   **本机能开、别的机器打不开**。
2. **托盘自启参数**：注册表 `HKCU\…\Run` 里的 `--port 8080` 是**写死的旧值**，
   重跑安装脚本会重写；没重跑就托盘点"打开管理界面"会去到 8080。
3. **数据目录里的 `server-overrides.json`**：它**优先于** `appsettings.json`。
   文件名存在说明端口曾被人工切换过（设置页改的），此时新默认值不生效——
   要么删掉该文件，要么在设置页把端口改成 8899。本机已确认**不存在**这个文件。
4. **客户机 Agent 不用改**：它从 UDP 发现/注册应答里拿 `HttpPort`，中心换端口会自动跟着走。

### 1.4 验证

- `dotnet build Server` / `build Agent`：**0 警告 0 错误**。
- 起来的实例只监听 `0.0.0.0:8899`，`/` 与 `/healthz` 均 200；8080 **无监听**。
- 前端产物 hash 变化（`index-c7HfR2cp.js`），服务端返回的就是它 ⇒ 磁盘优先路径生效。

## 2. 「页面被 Edge 强制关闭」

### 2.1 现场描述

- 表现：**只关掉当前标签页**，其它标签页都在；
- 时机：无明显规律；
- 环境：Edge 155，**没装代理软件**。

### 2.2 先排除掉的可能（都有证据，不是猜）

| 假设 | 怎么否掉的 |
|---|---|
| 服务端把页面踢了 | 首页与 `/healthz` 恒 200；Kestrel 日志里没有异常关闭记录 |
| 渲染进程崩溃 | `%LOCALAPPDATA%\Microsoft\Edge\User Data\Crashpad\reports` **没有转储**；Windows 事件日志无 `Application Error` |
| 扩展在关标签页 | 该 profile 只有一个官方扩展（`Edge relevant text changes`） |
| 企业策略强制关闭 | `HKLM/HKCU\SOFTWARE\Policies\Microsoft\Edge` **均不存在** |
| 系统代理劫持 | 用户确认没装；本机 `ProxyEnable = 0` |
| 页面自己调 `window.close()` | 全仓 0 处 |

### 2.3 真因：浏览器保留键，`preventDefault()` 拦不住

远控画面拿到焦点后，用户的意图是"在这些键上操作**被控机**"：

- 按 **Ctrl+W** 想关掉被控机上的窗口 → **关掉的是观看端自己的这个标签页**；
- 按 **Ctrl+R / F5** 想刷新那边的页面 → 刷新的是本页（画面重连、会话重建）；
- 按 **Ctrl+T / Ctrl+N** → 在观看端开了新标签/新窗口。

组件里其实早就写了 `event.preventDefault()`，注释也点出了这个场景
（`RemoteDesktopPanel.vue` 的 `onCanvasKeyDown`）。

**但那行代码对这几个键是无效的**：Chromium 把 Ctrl+W / Ctrl+R / F5 当**保留键**，
在把事件交给页面之前就已经执行完"关标签页/刷新"了。页面拿到 `keydown` 时，
标签页已经在关的路上了。

所以症状才会这么怪：**没有报错、没有崩溃页、控制台干净**，页面就是没了。

### 2.4 修法（两层，缺一不可）

**第一层：Keyboard Lock —— 全屏时把这几个键抢回来**

新增 `web/src/keyboardLock.ts`：

- `REMOTE_LOCKED_KEY_CODES` = `KeyW / KeyR / KeyT / KeyN / KeyP / KeyS / KeyO / F5`；
- 🔴 **不锁 `Escape`、`F11`、修饰键**：前两个是全屏的逃生通道，锁掉就退不出全屏了
  —— 那比误关标签页严重得多；修饰键锁住会让被控端的 Alt+Tab 失灵。
- `RemoteDesktopPanel.vue` 在 `fullscreenchange` 里：进全屏 → `lock`，退全屏 → `unlock`；
  组件卸载也 `unlock`（否则用户回到别的页面会发现 Ctrl+W 不响应了）。

**第二层：`beforeunload` —— 非全屏时的兜底**

Keyboard Lock **只在全屏可用**。没全屏时 Ctrl+W 依旧归浏览器，所以再加一道闸：

- 判据 `shouldWarnBeforeUnload(activeSessionId)`：**只在正在观看会话时**拦；
- 命中就 `preventDefault()`，Chromium 会先弹一次"离开此网站？"。

于是"页面突然消失"变成"页面问了一句，我点了取消"。

> 这层同时是**取证手段**：以后若再发生——
> **弹了确认框** ⇒ 是浏览器侧的关闭动作（键盘/鼠标/菜单）；
> **没弹框直接消失** ⇒ 进程被丢弃或杀掉，那才要往 Edge 的内存策略上查。

### 2.5 验证

- `keyboardLock.test.ts` **14 条**：能力检测、锁什么、锁不上怎么办、
  **逃生通道不在清单里**、`beforeunload` 判据；
- 前端总计 **177 / 177** 通过，`vue-tsc --noEmit` 干净；
- 系统 Edge 155 实测：`navigator.keyboard.lock/unlock` 均为函数、
  `document.fullscreenEnabled === true` ⇒ 第一层在这台机器上真的能生效。

### 2.6 没做 / 还挂着

- **非全屏时无法阻止 Ctrl+W**（浏览器不给这个能力），只能靠 `beforeunload` 问一句。
  页面上可以考虑加一句"建议全屏观看"，但会占用画面高度，暂不加。
- 如果是 Edge 的**标签页丢弃（内存策略）**而不是键盘：那只会让标签页变灰/重载，
  不会真的消失；真消失时 `beforeunload` 也不会弹 —— 届时按 §2.4 的判据走。
