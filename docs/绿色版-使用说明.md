# 中控服务版 —— 绿色版与服务版 使用说明

本产品有两种交付形态，**程序完全相同，差别只在"怎么启动、谁来停"**：

| 形态 | 产物 | 启动方式 | 停服务 |
|---|---|---|---|
| **绿色版** | `dist\win-x64\ControlServer.Server.exe`（**单文件**，约 49 MB） | 双击 exe | 右下角托盘 →「退出服务」 |
| **服务版** | `dist\win-x64-service\`（**2 个文件**，约 83 MB） | `install-service.ps1` 装成开机自启的 Windows 服务 | 右下角托盘 →「停止服务」 |

两种形态**都不需要**系统预装 .NET（self-contained）。

---

## 1. 怎么生成

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\windows\build-portable-exe.ps1
```

脚本做四件事：构建前端（Vite → `wwwroot`）→ 发布绿色版单文件 → 发布托盘助手并组装服务版目录 → **校验两个目录的文件数**。

常用参数：

| 参数 | 说明 |
|---|---|
| `-SkipWebBuild` | 跳过前端构建，直接用现有 `wwwroot` 产物 |
| `-SkipServiceOutput` | 只要绿色版单文件，不产出托盘助手与服务版目录 |
| `-NoCompression` | 关闭单文件压缩（体积变大，首次启动更快） |
| `-OutputDir <路径>` | 自定义绿色版输出目录（默认 `dist\win-x64`） |
| `-ServiceOutputDir <路径>` | 自定义服务版输出目录（默认 `dist\win-x64-service`） |
| `-DotNetRoot <路径>` | 指定 .NET SDK 目录（本机默认 `C:\Users\IYLONG\.workbuddy\binaries\dotnet8`） |
| `-NodeRoot <路径>` | 指定 Node 目录；传空字符串则跳过前端构建 |

> 服务版里的 `ControlServer.Server.exe` 是从绿色版目录**直接复制**的 —— 保证两者字节一致，不会出现"两个版本"。

## 2. 怎么用（绿色版）

**双击 `ControlServer.Server.exe` 即可。** 会发生三件事：

1. **右下角通知区域出现托盘图标**（本程序是 GUI 子系统程序，**不会**弹出控制台窗口）；
2. 服务开始监听 `0.0.0.0:8899`（HTTP）和 `9999/UDP`（对接码监听）；
3. **自动用系统默认浏览器打开** `http://localhost:8899/`。

默认账号：`admin` / `admin123`（登录后建议尽快在顶栏「修改密码」里改掉）。登录页可勾选「记住账号密码」，本机下次自动回填。

### 停止服务：右键托盘图标 →「退出服务」

**关掉浏览器、关掉任何窗口（包括启动它的那个 CMD 窗口），都不会停止服务** —— 服务跟着"托盘图标"活，只有从托盘菜单退出才会停。

托盘右键菜单（绿色版）：

| 菜单项 | 作用 |
|---|---|
| 打开管理界面 | 打开浏览器到 `http://localhost:8899/`（双击托盘图标同效） |
| 打开数据目录 / 打开日志目录 | 在资源管理器里打开 `%ProgramData%\ControlServer` 及其 `logs` |
| **退出服务** | **停止服务并退出进程** —— 需要管理员权限 |

### 从终端 / `run.cmd` 启动也一样

仓库根目录的 `run.cmd` 是"一键启动"脚本。用它会看到：

```
  ============================================================
    服务已启动：http://localhost:8899
    【关闭本窗口不会停止服务】-- 服务已在后台独立运行。
    停止服务：右键右下角托盘图标，选「退出服务」。
  ============================================================
```

**关闭那个 CMD 窗口，服务照常运行。**

原理：进程启动时会**主动脱离控制台**（调用 Win32 的 `FreeConsole`）。因为 Win32 的规则是 ——
控制台窗口被关闭时，系统会向**所有**挂在该控制台上的进程发 `CTRL_CLOSE_EVENT`，
而且**应用无法否决**（处理器返回 TRUE 也只能把死期从 0 秒拖到约 5 秒）。
所以"让服务扛住关窗"只有一条路：**先离开那个控制台**。脱离之后，那扇窗再被关掉就与它无关了。

代价是 **那个终端里看不到实时日志**了（日志照旧写 `%ProgramData%\ControlServer\logs\`）。

> **开发调试需要边跑边看日志？** 显式要求保留控制台：
>
> ```bat
> ControlServer.Server.exe --Server:Startup:AttachConsole=true
> ```
>
> 此时终端里能看到完整 Serilog 输出 —— 但**关掉该终端会同时停掉服务**（有意为之，只用于开发/排障）。
> 也可以在 `appsettings.json` 里写 `"Server": { "Startup": { "AttachConsole": true } }`，
> 或设环境变量 `Server__Startup__AttachConsole=true`。

> 首次双击可能等 **3～8 秒**才出页面 —— 单文件压缩包需要先解压到内存。
> 之后每次启动会快一些（Windows 会缓存）。

## 3. 局域网访问

同一局域网内任意电脑的浏览器打开：

```
http://<运行服务的机器IP>:8899
```

本机 IP 用 `ipconfig` 查。若其他电脑打不开，**需要放行防火墙**：

```powershell
# 管理员 PowerShell
New-NetFirewallRule -DisplayName "ControlServer HTTP" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8899
New-NetFirewallRule -DisplayName "ControlServer Pairing" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 9999
```

> `install-service.ps1` 会自动放行这两条规则，服务版不用手工做。

## 4. 改配置（端口 / 账号 / 数据目录）

exe **内置**了全套默认配置，开箱即用。要改的话，**在 exe 同目录放一个 `appsettings.json`** 即可 —— 只需写想改的项，其余沿用默认：

```json
{
  "Server": {
    "Http": { "Port": 9000 },
    "Listener": { "PairingPort": 9998 },
    "Auth": { "DefaultAdminPassword": "换一个强密码" },
    "Startup": { "AutoOpenBrowser": false }
  }
}
```

模板见仓库根目录 `appsettings.sample.json`。

几点说明：

- **改端口只需改 `Http.Port`**。绿色版**没有**内置 `Http.Urls`，程序会由 `Port` 自动推出监听地址 `http://0.0.0.0:{Port}`。
  只有要绑**特定网卡**时才写 `Http.Urls`（一旦写了，它就是这个值、优先生效，那时两处要一致）。
- 优先级（低 → 高）：**代码默认值 < exe 同目录 appsettings.json < 环境变量 < 命令行参数**。
  所以临时改端口也可以：`set Server__Http__Port=9000 && ControlServer.Server.exe`
- 之所以要专门支持"exe 同目录"，是因为**注册成 Windows 服务后工作目录是 `System32`**，默认的"按工作目录找配置文件"会失效 —— 现在两种形态行为一致。
- 改 `AutoOpenBrowser` 为 `false` 可关掉自动开浏览器（服务形态本来就会自动跳过）。
- 其它可用开关：`Server:Tray:Enabled`（`false` 则不起托盘，纯后台）、`Server:Startup:SingleInstance`（重复双击时是否只保留一个实例，默认 `true`，会静默打开浏览器后退出）、**`Server:Startup:AttachConsole`**（默认 `false` = 启动后主动脱离控制台，关掉启动它的终端不影响服务；设 `true` 则保留终端并在其中打印实时日志，代价是关终端会停服务 —— 详见 §2）。

## 5. 数据放在哪

`%ProgramData%\ControlServer\`

```
config/   配置与导入导出
files/    文件分发（M4）
images/   图片资源
logs/     Serilog 滚动日志（保留 31 天）
control.db  SQLite 数据库（含 -wal / -shm）
```

**exe 本身无状态** —— 换台机器拷过去双击即可跑；数据不会跟着 exe 走。

## 6. 可选：注册为开机自启的 Windows 服务（服务版）

不适合"双击运行"的场景（比如无人值守常驻、需要开机即启），用安装脚本：

```powershell
# 管理员 PowerShell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\windows\install-service.ps1
```

脚本会：

1. 复制程序到 `C:\Program Files\ControlServer`（Server + 托盘助手）；
2. 预建数据目录；
3. 注册服务（**含崩溃自动重启**的恢复策略）；
4. **授权交互用户可以启停本服务**（`sc sdset` 补 `SERVICE_START` / `SERVICE_STOP`）—— 托盘助手靠它才能停服务；
5. 放行防火墙；
6. 启动服务，并**部署托盘助手**（写 HKCU 启动项 + 立即拉起）。

### 为什么托盘助手是个独立进程？

Windows 服务跑在 **Session 0**（服务会话），那里没有 explorer、没有通知区域 —— **服务进程自己不可能显示托盘图标**，这不是实现问题而是会话模型决定的。所以托盘必须放到用户会话里，做成 `ControlServer.TrayAgent.exe`（约 34 MB）。

托盘助手只做四件事：显示图标 / 打开管理界面 / 启停服务（走 SCM）/ 退出。**不读配置、不读日志、不调管理 API、不传凭据** —— 所以它和主服务的版本不一致也不会坏。

### 服务版托盘菜单

| 菜单项 | 作用 |
|---|---|
| 服务状态：已启动 / 已停止 | 只读信息行 |
| 打开管理界面 | 只有服务在运行时可点 |
| **启动服务 / 停止服务** | 走 SCM；需要"交互用户"有对应权限（安装脚本已配好） |
| 打开数据目录 / 打开日志目录 | 在资源管理器里打开 |
| **退出托盘助手** | 只关掉托盘图标，**不影响服务运行** |

> **关于 HKCU 启动项**：启动项写在"当前登录用户"的注册表里，所以是**每个要用托盘的账号各装一次**（服务只需管理员装一次）。
> 如果安装脚本是用**另一个管理员账号**提权跑的，脚本会检测到并给出警告 —— 请在真正使用托盘的账号下再跑一次。

卸载：

```powershell
# 管理员 PowerShell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\windows\uninstall-service.ps1
```

会移除托盘助手（含 HKCU 启动项）、删除服务、删除程序目录与防火墙规则；**数据目录保留**。

## 7. 已知限制

- **exe 未做代码签名**。首次运行 Windows SmartScreen 可能提示"未知发布者"，点"更多信息 → 仍要运行"即可；企业环境如需静默分发，请购买代码签名证书。
- 单文件压缩包在**杀毒软件**里可能因"自解压到内存"被额外扫描，导致首次启动更慢。
- 服务版的托盘助手是**每用户**部署（HKCU 启动项），多用户共用一台机器时要逐个装。
- 目前只支持 `win-x64`。`linux-x64` 的自包含发布已验证可编译（托盘在 Linux 上是 Noop，不影响服务），但绿色版脚本尚未覆盖（`Runtime` 参数已预留）。

## 8. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 双击没看到控制台窗口 | **正常** —— 本程序是 GUI 子系统，日志改为写文件。看 `%ProgramData%\ControlServer\logs\*.log`；或加 `--Server:Startup:AttachConsole=true` 从终端看日志（见 §2） |
| 在 CMD 里启动，关掉 CMD 后服务也没了 | **默认不会** —— 进程启动时会主动脱离控制台（`FreeConsole`），关窗与它无关。若确实发生了，检查是不是自己加了 `--Server:Startup:AttachConsole=true`（那属于开发模式，预期行为） |
| 从终端启动后，终端里没有任何日志 | **正常** —— 默认脱离控制台；启动横幅由 `run.cmd` 自己打印，服务日志在 `logs\`。要实时日志加 `--Server:Startup:AttachConsole=true` |
| 右下角没有托盘图标 | 检查是否被折叠进"隐藏的图标"（点任务栏的 `^`）；绿色版确认 `Server:Tray:Enabled` 未被设为 `false`；服务版看 `%TEMP%\ControlServer.TrayAgent.log` |
| 双击后没反应 | 首次解压较慢，等几秒；或查看 `%ProgramData%\ControlServer\logs\*.log` |
| 关掉浏览器后服务还在跑 | **正常设计** —— 服务跟随托盘图标，请在托盘右键「退出服务」 |
| 第二个实例双击后直接退出 | **正常** —— 单实例保护：它会打开管理界面后退出（日志有 `检测到本机已有实例在运行`） |
| 浏览器没自动打开 | 无默认浏览器 / 被策略拦截 —— **不影响服务**，手动访问 `http://localhost:8899` |
| 局域网打不开 | 防火墙未放行 8899（见 §3） |
| 页面 404 / 白屏 | 极少见；确认发布时前端构建成功（脚本 `1/4` 步骤） |
| 服务版托盘点「停止服务」报"拒绝访问" | `sc sdset` 授权没成功。管理员执行 `sc.exe sdshow ControlServer` 检查 IU 的 ACE 是否含 `RP`/`WP`；或重跑安装脚本看 §4 步的输出 |
| 服务版托盘图标不出现 | 确认托盘助手进程在跑（`tasklist /FI "IMAGENAME eq ControlServer.TrayAgent.exe"`）；看 `%TEMP%\ControlServer.TrayAgent.log`；确认 HKCU 启动项写在**使用托盘的账号**下 |
