## 0. 一句话结论

**M6 的验收原话是「一线人员按文档能独立部署」。本轮把它做成了可执行的东西**：
一条 `--health` 把巡检变成"跑一条命令看退出码"，一份手册把故障判成"看哪几个键"，
一个演练脚本在**干净目录 + 全新数据目录 + 全新端口**上、用**打好的单文件 exe**
把"装 → 起 → 登录 → 改配置 → 巡检 → 备份 → 删库 → 恢复 → 逐项比对"走了一遍：**26 / 26 通过**。

顺带修掉两件原本会长期埋着的事：**业务日志只增不减**（现在有保留策略），
以及**日志落盘失败完全无声**（现在有一条 Error、`/healthz` 有 `logSink`、巡检有告警）。

## 1. 这块为什么必须做（不是"补文档"）

M6 方案 §0 说过一句判断，本轮被验证了：

> 🔴 「照着文档做一遍」这件事必须真做，不能"我读过一遍觉得能行"。**这一步最贵、也最容易糊弄，而它恰好是 M6 唯一真正的价值。**

真做下来，**演练本身抓出了 3 个缺陷**，全都不是"文档写错字"那一类：

| # | 演练/实测抓到的 | 如果不做这一步会怎样 |
|---|---|---|
| 1 | 业务日志 `logs/log-*.ndjson` **只增不减**，全仓没有删除逻辑 | 磁盘满的第一个信号是"日志悄悄断了"，而那时代码里的 `catch` 是静默丢弃 —— 现场无法归因 |
| 2 | 日志落盘失败**没有任何外部信号** | 同上，且连"日志断了"这件事本身都没人知道 |
| 3 | 落盘 JSON 把中文转义成 `\u65E5\u5FD7` | 现场 `findstr 授权 logs\log-*.ndjson` **一个字都匹配不上**，人会得出"日志里没有这条"的错误结论，然后往完全错的方向查 |

> 第 3 条是在演练里"顺手 grep 一下自己的日志"时撞出来的。它不影响任何功能测试，
> 只影响**人能不能排查** —— 而 M6.5 要的正是这个。这类缺陷只有"真的照着文档做一遍"才会暴露。

## 2. 代码：日志保留 + 写失败可见

### 2.1 保留策略（`Server:Logging`）

| 配置键 | 默认 | 说明 |
|---|---|---|
| `Server:Logging:RetentionEnabled` | `true` | 总开关。关掉 = 回到 M6.5 之前"只增不减" |
| `Server:Logging:RetentionDays` | `30` | 保留天数（含今天）。≤0 = 不按天数删 |
| `Server:Logging:RetentionMaxMegabytes` | `200` | 总量上限。≤0 = 不按总量删 |

**为什么两个上限都要有**：天数管"正常滚动"，总量管"某一天突然暴涨"（把级别调到 Debug 排查时，
一天能顶一个月）。只有天数的话，一次排查就能把盘占满。

实现要点（`Core/Services/LogRetention.cs` + `LogService.PruneIfDue`）：

| 决定 | 为什么 |
|---|---|
| 只碰 `log-YYYY-MM-DD.ndjson`，用**正则**而不是 `StartsWith` | `server-*.log` 是 Serilog 的，出事时最需要看；`log-*.ndjson.bak` 是运维手工留的证据。名字对不上一律不动，并如实列进 `IgnoredNames` |
| 按**文件名里的日期**判龄，不看 `LastWriteTime` | 复制/解压/恢复都会改写 mtime，那会把"上周的"判成"今天的"。与 M6.4 §5 拒绝用文件时间戳当版本标识是同一个理由 |
| **今天的文件永不删** | 删了它，"日志断了"就变成自己造的 |
| 清理放在**写之前**，每天首次落盘时跑一次 | 磁盘满的时候，清理旧日志正是解药。放在写之后，最需要它的那一刻反而永远轮不到 |
| 未来日期的文件不按年龄删 | 时钟回拨过会出现这种文件，它不是"过期"，它可能是最新的 |

### 2.2 写失败可见（三条通道）

改造前：

```csharp
catch { /* 日志落盘失败不得影响业务：静默丢弃本轮批量 */ }
```

"不拖垮业务"是对的，**"完全没有外部信号"是错的**。现在：

1. **连续失败从 0 变 1 时**往 Serilog 喊一声（`server-*.log` 一条 `[ERR]`），恢复时再喊一声；
   持续失败**不重复喊** —— 每 500 ms 喊一次会把另一条日志也刷爆，等于用日志问题制造第二个日志问题；
2. `/healthz` 新增 `logSink` 字段：`{ healthy, consecutiveFailures, lastError }`；
3. `--health` 把它转成一条 `warn.N`。

> 🔴 告警**必须走另一条通道**。接回 `LogService` 等于没接 —— 写不进去的正是那条通道本身。
> 所以宿主把它接到 Serilog（`server-*.log` + 控制台），两个文件、两套滚动策略，一个坏了另一个还在。

### 2.3 顺带修的：中文不再被转义

`JsonSerializer.Serialize(entry, FileJsonOptions)`，其中
`Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping`。

- **为什么必须改**：现场的排查动作是 `findstr 授权 logs\log-*.ndjson`，转义之后**零命中**；
- **为什么安全**：这些文件只在磁盘上被 grep / 打进备份，**从不作为 HTML 渲染**；
  HTTP 侧的 JSON 走 MVC 自己的序列化器，**不受这里影响**，注入面没有被搬回页面上。

## 3. 新增 `--health`：把巡检变成退出码

```
ControlServer.Server.exe --health
```

**输出契约**（与 `--dbinfo` 同源）：一行一项 `键=值`、**键名全 ASCII**、
末尾 `health=ok|warn|fail`、退出码 **0 / 1 / 2**。

- **为什么键名必须 ASCII**：同一个 exe 要在中文 Windows 控制台（码页 936 → 输出 GBK）、
  Git Bash（按 UTF-8 解码 ⇒ 中文全乱）、Linux（UTF-8）三处被脚本 grep。只有 ASCII 键三处都稳。
  本轮实测就是这个现象：Git Bash 里中文标题全是 `ʱ¼£` 这样的乱码，但 `db.bytes=5120000` 一字不差。
- **为什么退出码要分级**：定时任务只看退出码，不看内容。`0/1/2` 正好对应"什么都不做 / 发告警 / 叫值班"。

巡检项与判据：

| 键 | 判据 | 告警阈值 |
|---|---|---|
| `data.exists` / `db.bytes` | `data.exists=0` 或 `db.bytes=0` ⇒ **fail** | — |
| `db.bytes` | — | > 4 GB（M6.3 实测 100 台 30 天 ≈ 2.8 GB） |
| `db.wal.bytes` | — | > 256 MB（长时间没 checkpoint，重启回收） |
| `logs.bytes` | 用 `Server:Logging:RetentionMaxMegabytes` 当判据 | 超过配置上限 ⇒ 保留策略没生效 |
| `disk.free` vs `disk.needed` | `needed = max(5 GB, 数据目录 × 1.2)` | `free < needed` |
| `cert.server.daysleft` / `cert.ca.daysleft` | — | ≤ 30 天 |
| `license.daysleft` | — | ≤ 30 天（续期要客户配合） |
| `trial.daysleft` | — | ≤ **7** 天（见 §3.1） |
| `service.healthz` | 本机 `/healthz` 状态码 | `unreachable` ⇒ warn（维护窗口正常） |
| `logSink.healthy` | 从 `/healthz` 里取 | `false` |

`disk.needed` 用 **"数据目录 × 1.2"**，与 `deploy/upgrade/upgrade.ps1` 的余量检查**同源** ——
余量不够时升级会中途失败，所以巡检就该提前报。

### 3.1 🔴 试用 7 天、正式授权 30 天（刻意不同）

第一版两个都用 30 天，结果**一台刚从箱子里拆出来装好的机器第一天就带告警**（试用 30 天 ⇒ 剩 29 天）。
值班很快就会对"巡检有告警"脱敏，等真出事时就不看了。

- 试用续命 = 导一个文件，一小时能搞定 ⇒ **7 天**够；
- 正式授权续期 = 报价、付款、签发都要客户配合 ⇒ **30 天**是必要的。

改完之后，冷启动演练里"新装机器巡检零告警"这条才立得住（见 §4 第 4.6 步）。

## 4. 冷启动演练：实测

```bash
python deploy/drill/coldstart.py
```

**它凭什么算"干净"**：全新空目录当安装目录、**不存在**的数据目录、全新端口（连默认的
8080/9999/9998 都不用）、不写注册表、不建服务；跑完整个临时根目录删掉。

**它凭什么算"只照文档"**：每一步都对文档里**一条命令**，脚本把那条命令**原样**打出来，
再用文档自己写的成功判据去判。

### 4.1 演练之外，单独验了一次"保留策略真的会删"

单测能证明逻辑，**证明不了真包在真数据目录上的行为**（铁律 13：源码改了 ≠ 现场修好了）。
所以在打好的单文件 exe 上做了一次真机探针：

```
启动前 : log-2026-01-01.ndjson, log-2026-09-01.ndjson, log-2026-09-02.ndjson.bak, server-20260101.log
清理后 :                        log-2026-09-02.ndjson.bak, log-2026-10-17.ndjson, server-20260101.log, server-20261017.log
被删   : log-2026-01-01.ndjson, log-2026-09-01.ndjson
见证   : {"Message":"日志保留：按策略删掉 2 个过期文件（5.9 KB），留下 0 个（0 B）。策略 = 保留 30 天 / 上限 200 MB。"}
```

三件事同时被证：**该删的删了**、**不该动的（`.bak` 与 `server-*.log`）一个没动**、
**落盘文件里的中文能直接 grep 到**（`findstr 日志保留` 命中）。

> 这条探针第一次跑就抓出两处：消息里写的是 `0.0 MB`（5000 字节被四舍五入成 0，看起来像没删），
> 以及整份日志文件的中文是 `\u65E5\u5FD7` 转义。两处都改了才通过。

## 5. 文档：`docs/运维手册.md`

补的是方案 §3.4 要的三节 —— **巡检 / 故障树 / 容量** —— 外加一张"遇到什么事看哪份"的索引
（现场最贵的成本是"不知道翻哪份文档"）。

| 节 | 内容 | 关键点 |
|---|---|---|
| §0 | 文档索引 | 9 种场景 → 对应文档 |
| §1 | 一分钟体检 | `--health` 每个键的判读表 + 退出码 + **为什么必须提权** |
| §2 | 巡检 | 每周 5 分钟做什么、每月做什么、**巡检不包括什么** |
| §3 | 故障树 | 6 棵：起不来 / 打不开 / 点按钮没反应 / 日志断了 / 远控 / 升级后数据变少。每棵都给**能判死的证据**而不是"检查一下 X" |
| §4 | 容量 | 实测基线 + 换算公式 + 磁盘规划表 + 三个旋钮 |
| §5 | 变更窗口 | 1–2 分钟"按了没反应"，三条铁律 |
| §6 | 不能替你做 | 6 条 |

两个刻意写实的决定：

1. **§3.3「点按钮没反应」按概率排序**，不按"可疑程度"。现场问得最多的就是这条，
   而最常见的三个原因是**授权过期 / 客户端离线 / `ExecuteUdpCommands=false`**，都不是"按钮坏了"。
2. **§3.4 明写"永远不要删 logs/ 来解决问题"**。保留策略已经会按配置自动裁；
   手工删只会删掉排查唯一的证据 —— 而"日志太大"这个症状本身就该先查是谁在涨。

## 8. 挂账（本轮新增）

- **`-HardenDataDir` 仍未在真机装一遍验证**（M6.4 挂账，本轮没找到干净机器，原样挂着）；
- **服务以 LocalSystem 读写收紧后的数据目录未实测**（M6.4 挂账）；
- 冷启动演练没覆盖**安装包形态**与**服务形态**（见 §7 #2）；
- `--health` 的磁盘判据用的是 `DriveInfo(Path.GetPathRoot(...))`：数据目录在**挂载点/符号链接**上时
  可能取到不同的卷，未验证；
- 日志保留只在"一天一次"的粒度上验证；**跨天滚动那一刻**（文件名变化 + 清理同时发生）没有专门造场景；
- 手册 §3.3 的 6 条原因来自代码与既有冒烟，**没有**用真实故障逐条复现过；
- **`license.status=Expired` 那条告警分支没能端到端复现**：签发工具**拒绝**签发一份已过期的授权
  （`指定的到期时间早于签发时刻：签出去就是一份已过期的授权`）—— 这个拒绝是对的，代价是这条分支
  只能靠枚举语义与代码阅读保证。顺带说明：本轮顺手把这条判断从 `RemainingDays < 0` 改成了
  `Status == LicenseStatus.Expired` —— `LicenseState` 的口径是「**已过期为 0**」，
  而 `0` 同时也是「今天到期」的合法值，用 `< 0` 判会把过期说成「还有 0 天到期」。
