# M7.11 — 页面关于编码格式的文案：全错了，而且错了很久

> 现场看见的是这一条横幅（2026-10-19，用户截图）：
>
> > **画面还是 M5.1 的 MJPEG 联调脚手架**（每帧一张独立 JPEG），**不是可交付的编码格式**
> > —— 硬编器都不编 JPEG，所以帧率上不去（默认 12 fps）。4K60 要等 M5.4 的 H.264/HEVC 硬编。
>
> 而那一台机器**正在跑 H.264 硬编、57 fps**。

---

## 1. 这不是"文案有点旧"，是每一句都反了

| 横幅说的 | 事实（M7.4 之后） |
|---|---|
| 画面**还是** MJPEG | 硬编 H.264/HEVC 是**正常路径**；MJPEG 只在**多屏拼接**与**无硬编的机器**上出现 |
| MJPEG 是"**联调脚手架**" | 它是**接线正确的降级档**，在上面那两种场景里是**唯一**可行的选择 |
| **不是可交付的编码格式** | 它一直在交付（展厅里那些只有集显的机器全靠它） |
| 帧率**上不去（默认 12 fps）** | `smooth` 档实测 **57.1 fps**；`low/balanced/high` = 11.9 / 29.0 / 57.1 |
| **4K60 要等 M5.4** | M5.4 早就做完了 —— 4K 走硬编，不是"等" |

**为什么它能活这么久**：`docs/M5.4b-实施方案.md` 的 ④ 已经明确记过一句
「这条文案会直接误导现场判断，建议随前端那一路并行改动一起更新」——
但那轮没人回头改前端。于是这条横幅又挂了两个大版本。

🔴 **这条错误的代价是可以量化的**：现场看到"帧率上不去、4K60 要等下一期"，
就会以为**当前版本本来就这样**，从而不去查自己为什么只跑到十几帧
（真因往往是安全上下文缺失 ⇒ 降级到 MJPEG，见 §3）。

---

## 2. 顺带查出两处同类问题（同一个病灶：分期编号 + 断言式口吻）

### 2.1 「没有声音」那条横幅里藏着一句**说反了的话**

原文：

> **画面与键鼠回传都不受影响**（M5.1 的 MJPEG 走的是 `<img>`，没有这个限制）。

前半句在**硬编路径下是错的**：H.264 / HEVC 走的是 WebCodecs `VideoDecoder`，
它和 `AudioDecoder` 一样**只在安全上下文里存在** ⇒ 硬编这一路在
`http://192.168.x.x` 下**根本建不起来**。画面之所以还看得见，是因为
**降级到了 MJPEG**（`<img>`），而不是"画面没有这个限制"。

⚠️ 这两种说法对现场含义完全不同：

- 正确说法 ⇒ "你能看，但看的不是硬编" ⇒ 会去装证书；
- 原文的说法 ⇒ "https 只影响声音" ⇒ 不装证书，然后一直奇怪自己的 4K 为什么只有十几帧。

现在改成：**画面会降级到 MJPEG，所以看得见，但帧率与清晰度都达不到硬编。**

### 2.2 模板里还在对用户说 `M5.1`

| 位置 | 原文 | 现在 |
|---|---|---|
| 面板标题 | `远程桌面（M5.1 观看 + M5.2 键鼠回传 + M5.3 声音）` | `远程桌面` |
| 能力提示 | `没报出任何硬编格式 ⇒ M5.1 只能用 MJPEG 软编` | `⇒ 这台机器只能走 MJPEG 软编，帧率与清晰度都受限` |
| 会话列表空态 | `M5.1 每台机器最多一路` | `每台机器同时只保留一路` |

分期编号是**内部里程碑**，对现场没有任何信息量；而"声音"能不能用其实只取决于
一个前提（安全上下文），跟"做没做 M5.3"无关。

## 3. 改法：把"怎么说"从组件里搬出来，变成可断言的纯函数

新增 `web/src/codecFallback.ts`：

```ts
export function codecLabel(codec): string              // mjpeg → 「MJPEG（降级）」
export function describeCodecFallback(codec): string | null
```

- **只在 `codec === 'mjpeg'` 时**返回一句话，其余一切情况返回 `null`；
- 那句话只说**事实与出路**（软编、低于硬编、要看细节切单块屏、要 60 帧走硬编），
  **不猜原因** —— 原因有三条完全不同的来路（拼接只能软编 / 本机没硬编 /
  浏览器只声明了 MJPEG），前端只能确定地判其中一部分，猜错会把排查引到错方向。
  原因由被控端的 `codecNote` 说（它裁决完自己写的那句人话）。

🔴 **为什么必须抽成纯函数**：这句话是本仓最容易长期说谎的一处 ——
它说的正是"这一路现在是什么、为什么不如人"。留在组件里就只能靠人肉眼发现；
抽出来以后 `codecFallback.test.ts`（7 条）会挡住：

- 硬编会话**一句话都不说**（`null`）；
- `mjpeg` 的标签**不含**「脚手架」「联调」；
- 提示里必须**同时**给出"是什么"（软编/降级）与"往哪走"（单块屏/60 帧）；
- 提示里**不许**出现 `M\d.\d` 这类里程碑编号。

同时**整条常驻横幅删除**：一条"总是出现、且只讲坏消息"的横幅，
最后一定会被所有人当背景噪声无视 —— 那时它连"真的降级了"都提示不到。

## 6. 现场要知道的两件事

1. 🔴 **服务是我停掉的**（编译要写 `bin\Debug\net8.0\ControlServer.Server.exe`，
   而它正被那个实例锁着）。重跑一次 `run.cmd` 即可 ——
   它以 `src\ControlServer.Server` 为工作目录，**磁盘 `wwwroot` 优先**，
   所以起来就是新页面，不用再 build 前端。
2. ⚠️ 用**普通权限**起服务时，业务日志写不进去：

   ```
   [ERR] 业务日志写入失败：C:\ProgramData\ControlServer\logs\log-2026-10-19.ndjson
         UnauthorizedAccessException: Access to the path ... is denied.
   ```

   那是 ACL 收紧之后的表现（日志文件原先由提权进程创建）。不影响远控功能，
   但**「日志」页面会停止更新**。处置：用管理员权限起服务，
   或对 `logs` 目录重新授予当前用户写权限（**不要**删日志文件）。
