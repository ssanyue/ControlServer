## 0. 先把 M6 的判据翻译成能测的东西

原文那句「一线人员按文档能独立部署」不是判据，是愿望。M6 的每一块都得换成一个**可执行的验收动作**：

| 块 | 原文 | 换成可测的判据 |
|---|---|---|
| 安全审计 | 通过 checklist | 一张**逐项给证据**的清单（代码位置或测试名），且「不适用」要写理由 |
| 压测 | 20/50/100 台 | 100 台在线 30 分钟：中心 CPU/内存、心跳延迟 p95、**命令到达率**、**推流到达率**、掉线重连成功率，**逐条达标**（门槛见 §7②，已由实测曲线回填） |

> 🔴 **原写的是「命令回执 p95」—— 这个词在本协议里没有对应物**（`Command` 是单向推送、无回执，
> 中心回 200 只代表"已交给长连接"）。`docs/M6.3-压测报告.md` §6 把它拆成两个**能量**的事实：
> **到达率**（假机器实收 ÷ 中心下发）＋ **下发 HTTP P95**。验收表若继续写"回执"，就是一条无法证伪的指标。
| 安装包 | 有安装包 | **升级不丢数据**；**回滚**有可执行路径（不是"重装一遍"） |
| 运维文档 | 有文档 | 在**一台干净机器**上，只照文档，从零装到能用（冷启动演练） |

> 🔴 **「照着文档做一遍」这件事必须真做**，不能"我读过一遍觉得能行"。

## 2. 三个必须先说清的坑（它们决定 M6 要**改东西**，不是只写文档）

### 2.1 🔴 WAL 模式下，**直接拷 `control.db` 是假备份**

`DatabaseInitializer` 显式开了 WAL：

```csharp
await _db.Database.ExecuteSqlRawAsync("PRAGMA journal_mode=WAL;", ...);
```

⇒ 运行时的 `control.db` **不是完整状态**：还有 `control.db-wal` / `-shm`，而 checkpoint 时机由 SQLite 决定。
一个"把数据目录打包"的脚本会**每天产出一份看起来正常、恢复时少最后一段时间**的备份 ——
这种错误**在备份当天完全看不出来**，只在真恢复那天爆。

**做法**（两条，选更稳的第一条）：

| 方式 | 命令 | 适用 |
|---|---|---|
| **在线快照（推荐）** | `VACUUM INTO 'backup-<时间>.db'` | 服务在跑也能做；产出**单文件一致性快照** |
| 停机拷贝 | `PRAGMA wal_checkpoint(TRUNCATE)` 后拷 `db`/`-wal`/`-shm` 三个 | 只能在停服窗口做，漏一个就废 |

🔴 **不许**用 `cp control.db` / `Copy-Item control.db` 这种"看着对"的写法。

### 2.2 🔴 日志**只追加、永不删**

`LogService.FlushAsync` 每天一个文件 `logs/log-YYYY-MM-DD.ndjson`，`File.AppendAllTextAsync` 追加，
**没有任何保留策略**（全仓搜不到 retention / trim）。后果两条：

1. 备份体积随服役时间线性增长；
2. **磁盘满**——而 `FlushAsync` 的 `catch` 是**静默丢弃**（写日志失败不得影响业务，这是对的），
   所以"磁盘满"在现场的**第一个症状不是报错，是日志断了**，很难查。

⇒ M6 必须二选一，**不写就等于埋雷**：
- (A) 加保留策略（N 天 / 总量上限，启动时与每天滚动时清理）；
- (B) 写进《运维巡检》"每周手工清理 `logs/`，保留最近 14 天"，并给一条可直接粘的命令。

### 2.3 🔴 「100 台」不能靠起 100 个真 Agent

每台 Agent ＝ **Windows 服务 ＋ 托盘两个进程**，托盘必须有桌面会话 ⇒ 本机连 3 台都摆不平，
更别说 100 台。而且真 Agent 的瓶颈是**抓屏 + GPU 编码**，那是**被控端**的事，不是中心的事。

**正解：协议级假 Agent。** 复用真 Agent 的连接代码（`X-Agent-Key` 握手 ＋ `/hubs/agent`），
**只把"抓屏/编码"换成脚本化数据**，分三层测，每层各自有判据：

| 层 | 起多少 | 测什么 | 关键指标 |
|---|---|---|---|
| **L1 连接与心跳** | 100 个连接（**单进程多连接**） | 中心能不能扛住 100 路长连接 ＋ 心跳/遥测落库 | 中心 CPU、内存、GC、遥测批量写延迟、掉线重连成功率 |
| **L2 命令下发** | 100 台里挑 100 台 | 批量执行动作的回执 | 回执 p95、漏命令数、中心队列深度 |
| **L3 远控推流** | **1–2 路**（明确不做 100 路） | 推流路径在"有 100 台在线"时是否被压坏 | 帧时延、解码重建次数、丢帧 |

> ⚠️ **必须写进报告的一句**：**压测测的是中心，不是被控端。**
> "100 台在线"在真机上每台还要各自跑抓屏与硬编（本机物理不可得，见 M5.4-c §6.1），
> 所以这份报告**不能**用来承诺"100 台 4K 远控"。它只回答"中心这一侧会不会先垮"。

### 3.3 安装包：补「升级」与「回滚」两条腿

已有的是「装」与「卸」，缺的是**升级**和**回滚**，而这两件事各有一个人人都会踩的坑：

| 场景 | 做法 | ⚠️ 坑 |
|---|---|---|
| 升级 | 覆盖安装（**数据目录不动**，版本号进安装包） | 启动时 `Migrate()` 会自动升级数据库 —— **这一步不可逆** |

⇒ M6.4 的交付物是一条**可执行的**回滚步骤，不是一句"重装即可"；并且它和 M6.1（备份）**强耦合**：
**没有备份就没有回滚**。这两块必须一起做。

### 3.4 运维文档：补《巡检 · 故障 · 容量》三节

现有四份文档讲的是"怎么装、怎么用"，缺的是"**跑起来之后怎么盯、坏了怎么判**"：

- **巡检**（每周/每月）：磁盘余量、`logs/` 体积、`control.db` 与 `-wal` 体积、证书到期日、`/healthz`、授权到期日；

  能开但按钮没反应（授权过期 / Agent 掉线 / `ExecuteUdpCommands=false`）、
  **日志断了**（见 §2.2，第一个怀疑磁盘）；
- **容量**：每台 Agent 每天的遥测行数与磁盘占用（**要实测**，不能估）。

**✅ 结果（M6.5）**：三节都补了 —— `docs/运维手册.md`（§2 巡检 / §3 故障树 / §4 容量），
外加一张"遇到什么事看哪份"的索引。但**没有停在"补文档"**：

1. 巡检不能是"请依次检查五六条" —— 那现场会敲两条就走神。所以新增
   `ControlServer.Server.exe --health`：一条命令、ASCII 键值输出、分级退出码（0/1/2），
   手册里每个"请检查 X"都换成了这一条命令的一个键；
2. §2.2 那条"日志只增不减"必须**改代码**（§7③ 已定 (A)）：`Server:Logging` 三个键，

   变成三条可见信号（`server-*.log` 一条 ERR ＋ `/healthz` 的 `logSink` ＋ `--health` 告警）；
3. 容量全部用 M6.3 的**实测数**换算（每台每天 17 280 行 ≈ 0.93 MB），不估。

演练脚本 `deploy/drill/coldstart.py`：干净目录 + 全新数据目录 + 全新端口，用**打好的单文件 exe**
走完 26 步，**26/26 通过**。它抓出了 3 个不修功能测试也发现不了的缺陷（日志只增不减 /
写失败无声 / 落盘中文被转义成 `\u` 导致 `findstr` 零命中）。

### 3.5 备份恢复：脚本 ＋ 演练 ＝ 一个闭环

> **状态：✅ 已交付（M6.1 收官）**，落地清单与实测数据见 §3.5.1。

- **谁执行 `VACUUM INTO`**：**服务自己的 exe**（`ControlServer.Server.exe --backup <目录>`），
  不是外部脚本。理由：现场 Windows 上有没有 `sqlite3.exe` 完全看运气，而另发一个小工具
  又多一个"要跟主程序版本对齐"的东西。同一个 exe 里，SQLite 引擎与数据目录解析都不用重写。
- **脚本只做薄壳**：`deploy/backup/backup.ps1` / `backup.sh` —— 找程序、拼一个带时间戳的目录、
  透传退出码。**不再实现一遍备份逻辑**，否则迟早出现"脚本版"和"程序版"两个会分叉的实现。
- **恢复**：`--restore <目录> [--force]` —— 先全部校验（大小 ＋ SHA256），一个字节都不写；
  校验过了才覆盖。`--force` 是"我要覆盖已有数据库"的确认开关。
- **演练（真做）**：备份 → **删掉整个数据目录** → 恢复 → 逐项比对：
  用户数 / 配置文档数 / 审计条数 / 文件仓库摘要 / `license.lic` 哈希 / 迁移历史条数。
  **任何一项对不上就算没过。**

#### 3.5.1 🔴 一处**必须改正的原设计**：证书不进备份

原稿写的是"文件仓库、配置、授权、**证书**按目录打包"。**这条是错的**，而且错得很危险：

`IDataDirectory.CertificateDirectory` 的接口注释已经把话说死了 ——
> 🔥 它放的是"私钥"，不是普通数据 —— 这个目录的访问权限就是整条链路的安全边界
> （拿到根 CA 私钥的人可以给任何观看端签一张它认的证书，从而冒充中控服务）。
> 所以它**不许**被放进备份 / 分发 / 日志导出里。

照原稿做，等于**每一份备份都是一张可以冒充本服务的通行证**，而且它会被拷到移动硬盘、
NAS、别人的机器上 —— 那份私钥从此再也不在"这台机器的权限边界"之内了。

**改正后的口径：**

| 东西 | 进不进备份 | 为什么 |
|---|---|---|
| `https/ca.pfx`、`server.pfx`、`pfx.password` | ❌ | 私钥与口令。属于**这台机器**，不属于这份数据 |
| `https/controlserver-ca.crt` | ✅ | 根 CA 的**公钥**，本来就要分发给观看端；留着它才能判断"恢复前后是不是同一个 CA" |
| `downloads/` | ❌ | Agent 安装包（现场实测单个 65 MB），随时能从发布源重取 |
| `logs/` | ❌（默认） | 体积随天数线性增长，且不属于"恢复后必须一模一样"的数据。`--include-logs` 可显式加 |
| `control.db-wal` / `-shm` | ❌ | 那是中途状态。快照已由 `VACUUM INTO` 合成自洽的单文件 |

恢复时**不碰** `https/`：它是这台机器的身份，不是数据。删掉它会让所有已信任本服务的观看端
一起失效（得重新分发根证书）。

**"没备"必须写进产物**：`manifest.json` 里有一个 `skipped` 数组，逐项写明"跳过了什么、为什么"。
不写的话，下一个人看到备份里没有 `https/`，会当成漏备然后"顺手补上" —— 那才是真的把门打开了。

#### 3.5.2 实测（真机，现场数据目录的一份副本）

| 项 | 结果 |
|---|---|
| 数据目录内容 | `control.db` 5.1 MB ＋ 文件仓库 **1.02 GB**（一个真实上传的 zip）＋ 配置/授权若干 |
| 备份耗时 | **9.71 s**（含 1 GB 文件仓库） |
| 恢复耗时 | **7.11 s** |
| 备份产物 | 6 个文件 / 1026.9 MB / 跳过 4 项 |
| 六项比对 | 用户 1、配置文档 1、审计 11、文件仓库摘要、`license.lic` 哈希、迁移历史 13 —— **逐项一致** |
| `pragma integrity_check` | `ok` |
| 恢复后遗留的 `-wal` / `-shm` | 无 |

⚠️ **容量结论**：备份体积**基本等于文件仓库体积**（1 GB 级），而且目前是**全量**。
10 台以内的展厅可以接受；文件仓库长期增长后需要"增量 + 保留 N 份"的策略 —— 这一条**没做**，
记在 §7 待确认。

#### 3.5.3 四条**诚实的边界**

1. **恢复必须停服，这条不能通融**：服务在跑时，它会在恢复**之后**把内存里的旧数据写回库，
   于是"恢复成功但数据还是旧的" —— 比直接失败危险得多。命令会独占探测并给出可读的提示。
2. **`ps1` 的那一行"调用程序"没在本机端到端验过**：验证环境的安全策略不允许脚本启动原生
   可执行文件。所以它刻意保持成最朴素的透传（不解析输出、不改退出码），并且提供了
   `-DryRun` 让路径拼装与拒绝规则可以被单独验证。`sh` 版**有**端到端证据（见 §3.5.2 同环境）。
3. **`.ps1` 必须是 UTF-8 with BOM**：Windows PowerShell 5.1 按 ANSI 读无 BOM 的脚本，
   中文会乱码到连语法都报错（`<` 被当成保留运算符）。这是实测踩出来的，不是预防性建议。
4. **控制台输出只用中文与 GBK 里有的符号**（`√` / `×`）：中文 Windows 控制台码页是 936，
   emoji 编不出来会静默变成 `?`，于是"√ 备份完成"在现场显示成"? 备份完成"。

#### 3.5.4 落地与"怎么验的"

**代码与脚本**

如果这条对照不红，说明"假备份"这个陷阱根本没被复现，后面那条绿也就没有意义。

| 1 | `VACUUM INTO` 换成 `File.Copy` | **恰好 2 红**：WAL 用例 ＋ 删库恢复用例（后者也是因为拷主库丢了热数据） |

**演练当场抓到的三个真问题**（都不是"设计没想清楚"，是"写了但想错了"）

1. 🔴 **恢复要求数据目录已存在** —— 而"删了库再恢复"正是这条命令唯一的正经用法。
   第一次演练直接卡在 `【失败】这个数据目录不存在`。
2. 🔴 **`--help` 会让程序空引用崩溃** —— `TryParse` 对 `--help` 返回了 true，却没给 `invocation` 赋值。

3. 🔴 **"保留控制台"被写成了 `AttachConsole(父进程)`** —— 在 ConPTY / 父进程接管的场景下
   stdout 句柄被换走，**维护命令整段无输出**。正确做法是**根本不动控制台**：
   它本来就跑在用户的终端里。

## 5. M6 不许破的既有铁律

1. 新增 `/api` ⇒ 必须进 `LicenseGate` 分类表（否则被拦，测试会先红）；
2. 新增控制器 ⇒ `[Authorize]` 或显式 `[AllowAnonymous]`（匿名要写理由）；
3. 回归口径 = **总计 == 基线 ＋ 新增**，不是"失败 0"；
4. 压测 / 冒烟**不许绑固定端口**（开发机装了开机自启 Agent ⇒ 稳红）；
5. 构建时前后端不并行、编译加 `-m:1` 判 0 警告；
6. **压测不许碰现场数据目录**（临时目录 + 临时库）。
