## 6. 这份报告不能说明什么

- 🔴 **测的是中心，不是被控端。** 假 Agent 不抓屏、不编码、不推真码流 ⇒ **不能**用它承诺"100 台 4K 远控"。真机每台还要各自跑抓屏与硬编（本机物理不可得）。
- 帧是随机字节：中心不解码只转发，对中心的压力真实，但**测不到浏览器解码**的开销。
- 没有采集 GC 次数 / GC 暂停 / 线程池队列长度（要 `dotnet-counters`，本工具不带）。
- 所有假机器都注册在目标实例的库里。**必须用临时数据目录起的实例**，跑完把那个目录删掉 —— 否则在线表里会留下 N 台不存在的机器。
- 🔴 **「峰值在线」是假机器自报的（客户端视角），不是中心侧的连接表。** 中心进程被强杀时 TCP 不会立刻断，客户端要连败 3 次心跳才判定断线；那 20–30 秒里报告仍显示满员，而中心其实已经什么都没有了。 要量"中心认为几台在线"必须查中心的表，本工具不替代它。
- 🔴 **短于 5 分钟的轮次，别信"内存有没有一路涨"这一行。** 这台机器光启动预热（JIT + 首次迁移 + N 台同时握手）就要 60–90 秒，前 20% 的热身段不够长 ⇒ 会把"还在爬坡"读成"涨了 X%"（实测 3 分钟那轮报了 +12.1%，而同配置跑满 30 分钟是 −5.8%）。
- CPU/内存按**启动时那个 PID** 采。若中心中途重启（升级演练），后面几段会是 `—`——那是"采不到"，不是"占用 0"；改采新 PID 需要重开一轮。
- Linux / Docker 侧未在本轮覆盖（沿用既有挂账）。
